Dựng sân tập EduCommerce — Angular chế độ NgModule

Một project Angular chạy được, cố tình cấu hình theo kiểu Classic, để mọi bài sau có chỗ đổ code vào.

⏱ ~20 phút · 🎯 ng serve lên trang, pnpm test ra xanh · 🏷️ EduCommerce

🎯 Sau bài này bạn phải làm được
  • Có thư mục educommerce-ng-classic/ chạy được bằng ng serve.
  • Mở src/app/app.module.ts và chỉ đúng ra đâu là declarations, đâu là imports, đâu là bootstrap.
  • Giải thích được cờ --no-standalone làm gì và vì sao khoá này cần nó.
  • Chạy được một file .spec.ts RxJS thuần (không cần Angular TestBed) — đây là sân tập của Bài 01.
🌉 Bắc cầu từ cái bạn đã biết

Bạn đã chạy ng new rồi. Bài này không dạy lại ng new. Nó chỉ giải thích hai cờ khiến project sinh ra khác hẳn mặc định năm 2026, và ba chỗ Angular hôm nay đã khác codebase Angular 12–16 mà bạn sẽ gặp ngoài đời.

Bài này chỉ thêm một mảnh mới: một project Angular hiện đại vẫn có thể bị "kéo ngược" về kiến trúc NgModule một cách hợp lệ.

1. Vì sao không cài thẳng Angular 16 cho giống thật?

Lộ trình của bạn định nghĩa "Angular Classic" là ~v12–v16. Đó là lựa chọn đúng về mục tiêu — nhưng vấp một rào chắn vật lý:

Thứ Máy bạn đang có Angular 16 cần
Node.js v24.18.0 v16.14 hoặc v18.10
TypeScript đi kèm Angular 22: ~6.0.2 >=4.9 <5.2

Angular 16 sẽ không chạy trên Node 24. Muốn dùng nó thật thì phải cài nvm, nuôi song song hai bản Node, và Giai đoạn 2 phải ng update qua 6 major version. Bạn đã chọn hướng còn lại: dùng Angular mới nhất nhưng bật chế độ NgModule.

🤔 Vậy học thế có "giả" không?

Không, với điều kiện bạn biết chỗ nào lệch. Cái bạn cần học ở Giai đoạn 1 là mental model: NgModule gom khai báo, DI phân tầng theo injector tree, RxJS quản lý luồng bất đồng bộ, class Guard/Interceptor. Toàn bộ những thứ đó vẫn còn nguyên và vẫn stable ở Angular 22. Thứ đã đổi chỉ là vài API ngoại vi — và tôi sẽ chỉ đích danh từng cái, ngay khi bạn chạm vào nó.

💡 Vì sao KHÔNG cài ng global

CLI global là nguồn bug kinh điển: máy bạn có ng v17, project cần v22, và bạn ngồi debug lỗi schematic suốt buổi chiều. Ta dùng pnpm dlx để gọi đúng version một lần cho bước ng new; sau đó project có @angular/cli riêng trong devDependencies và mọi lệnh ng chạy qua pnpm sẽ tự lấy đúng bản của project.

🔥 Bẫy cú pháp: pnpm dlx KHÁC npx

Với npx bạn viết npx -p @angular/cli@22 ng new ... — cờ -p chỉ gói, rồi mới tới lệnh. Với pnpm dlx thì tên gói đứng ngay sau dlx, và pnpm tự chạy binary ng của gói đó. Nên phần còn lại phải là new ..., không phải ng new ....

Viết nhầm pnpm dlx @angular/cli@22 ng new ... sẽ ra lỗi trông rất khó hiểu — nó tải gói về xong mới báo:

lỗi thật khi viết sai (tôi đã đâm vào lúc soạn bài này) 
Error: Unknown arguments: standalone, routing, style,
file-name-style-guide, skip-git, defaults, package-manager, ng, new,
educommerce-ng-classic

Thông báo không hề nói "bạn thừa chữ ng" — nó liệt kê mọi tham số như thể sai hết. Chữ ng bị hiểu thành đối số, kéo theo toàn bộ phần sau lệch nghĩa.

Từng cờ có lý do, không cờ nào thừa:

CờNó làm gìVì sao khoá này cần
--no-standalone Sinh app.module.ts + app-routing.module.ts, và gắn standalone: false vào component Cờ quan trọng nhất của khoá. Không có nó, Angular 22 sinh project standalone và toàn bộ Giai đoạn 1 mất chỗ đứng.
--routing Tạo sẵn AppRoutingModule với RouterModule.forRoot([]) Phase 2 sẽ đổ lazy-load route vào đúng file này.
--style=scss Component dùng .scss Gần như mọi codebase Angular doanh nghiệp đều SCSS.
--file-name-style-guide=2016 Đặt tên app.component.ts thay vì app.ts Angular 22 mặc định kiểu tên mới (2025). Codebase cũ bạn sẽ maintain dùng kiểu 2016 — tập đọc đúng thứ bạn sẽ gặp.
--skip-git Không tạo git repo con Workspace ngoài đã là một repo; lồng repo trong repo gây rối.
--defaults Bỏ qua mọi câu hỏi tương tác Để lệnh chạy y hệt nhau trên máy bạn và máy tôi — không lệch do trả lời prompt khác nhau.
--package-manager=pnpm Dùng pnpm để cài dependency, và ghi "packageManager": "pnpm@11.13.1" vào package.json Trường packageManager khoá cả team (và CI) vào đúng một trình quản lý gói — hết cảnh người dùng npm, người dùng pnpm, sinh ra hai lockfile đánh nhau.
⚖️ Cờ --standalone vẫn còn, nhưng đừng chủ quan

Tại thời điểm viết bài (Angular CLI 22.1.4), ng new --help vẫn liệt kê --standalone [boolean] [default: true] — nên --no-standalone hợp lệ. Angular team đang đẩy mạnh standalone, nên một ngày nào đó cờ này có thể biến mất. Cách kiểm nhanh, luôn đúng, không cần tin bài viết nào: pnpm dlx @angular/cli@22 new --help.

4. Đọc thứ vừa sinh ra — và ba chỗ đã khác v16

Đây là phần đáng giá nhất của bài. Mở src/app/app.module.ts:

TypeScript · src/app/app.module.ts (nguyên văn CLI sinh ra) 
import { NgModule, provideBrowserGlobalErrorListeners } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';

import { AppRoutingModule } from './app-routing.module';
import { App } from './app.component';

@NgModule({
  // declarations = component/directive/pipe THUỘC VỀ module này.
  // Một component chỉ được declare ở ĐÚNG MỘT module — nhớ kỹ, Phase 1 sẽ đá vào đây.
  declarations: [
    App
  ],
  // imports = kéo module KHÁC vào để dùng những gì module đó export.
  imports: [
    BrowserModule,
    AppRoutingModule
  ],
  // providers = đăng ký service ở tầng injector của module này.
  // Bài 0.3 sẽ đào đúng dòng này: vì sao đặt ở đây khác đặt ở component.
  providers: [
    provideBrowserGlobalErrorListeners(),
  ],
  // bootstrap = component gốc được dựng khi app khởi động.
  bootstrap: [App]
})
export class AppModule { }

Bốn khoá declarations / imports / providers / bootstrap chính là toàn bộ Giai đoạn 1 thu nhỏ. Nhưng có ba chi tiết khác codebase v12–v16 mà bạn phải biết ngay, kẻo sau này đọc code cũ lại tưởng mình sai:

#Angular 12–16Angular 22 (bạn đang cầm)
1 platformBrowserDynamic().bootstrapModule(AppModule)
từ @angular/platform-browser-dynamic		 platformBrowser().bootstrapModule(AppModule)
gói platform-browser-dynamic không còn trong deps
2 @Component không có khoá standalone standalone: false phải ghi tường minh ở mỗi component NgModule
3 Test chạy bằng Karma + Jasmine Mặc định là Vitest (describe/it/expect + vi)
🔥 Chỗ này cắn người thật

Điểm số 2 là bẫy hay gặp nhất khi maintain codebase đang migrate dở: bạn tạo component mới bằng ng generate component, quên standalone: false, rồi thêm nó vào declarations → Angular ném lỗi kiểu "Component X is standalone, and cannot be declared in an NgModule". Không phải lỗi cú pháp — là hai mô hình khai báo đang cãi nhau.

6. Sanity check 2 — sân tập cho Bài 01

Bài 01 học RxJS. RxJS không cần Angular để chạy — và ta sẽ tận dụng điều đó: viết RxJS trong file test, chạy bằng Vitest, nhận phản hồi xanh/đỏ trong chưa tới một giây. Đó là feedback loop chặt hơn hẳn việc mở browser bấm thử rồi nhìn console.log.

bash · tạo thư mục sân tập 
# Thư mục này chưa tồn tại nên phải tạo tường minh
mkdir -p src/playground

Tạo file src/playground/sanity.spec.ts trong editor rồi dán nội dung sau:

TypeScript · src/playground/sanity.spec.ts 
import { describe, it, expect } from 'vitest';
import { of, firstValueFrom } from 'rxjs';
import { map } from 'rxjs/operators';

describe('sân tập', () => {

  // Test 1: chứng minh test runner sống.
  it('bộ máy test chạy', () => {
    expect(1 + 1).toBe(2);
  });

  // Test 2: chứng minh RxJS chạy được KHÔNG cần TestBed của Angular.
  // firstValueFrom biến Observable thành Promise để await trong test.
  it('RxJS chạy không cần Angular TestBed', async () => {
    const ketQua = await firstValueFrom(
      of(1).pipe(map((x) => x + 1))
    );
    expect(ketQua).toBe(2);
  });

});
bash · chạy test 
pnpm test

Kết quả cần thấy — Test Files và Tests đều màu xanh:

output thật (đã verify trên Node v24.18.0) 
 RUN  v4.1.10

 Test Files  2 passed (2)
      Tests  4 passed (4)
🔎 Vì sao 2 file / 4 test mà bạn chỉ viết 1 file / 2 test?

File thứ hai là app.component.spec.ts do CLI sinh sẵn, chứa sẵn 2 test (tạo được component + render đúng tiêu đề). 2 + 2 = 4. Nếu con số của bạn khớp đúng như trên, toàn bộ chuỗi công cụ đã đúng.

7. Đối chiếu tài liệu chính thức

Theo bảng version support chính thức, Angular 22.0.x yêu cầu Node ^22.22.3 || ^24.15.0 || ^26.0.0 và TypeScript >=6.0.0 <6.1.0 — Node v24.18.0 của bạn nằm trong khoảng hợp lệ. Danh sách cờ của ng new tra tại angular.dev/cli/new.
