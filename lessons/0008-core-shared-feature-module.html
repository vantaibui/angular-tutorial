Bài 07 bạn học injector tree: provider ở module eager gộp vào injector gốc, chỉ module lazy mới có injector riêng. Bạn cũng tự suy ra được câu hỏi cuối bài: import CoreModule hai lần thì sao?

Bài này chỉ thêm một mảnh mới: quy ước ba module là cách biến luật injector đó thành kiến trúc kiểm soát được.

1. Bài toán thật: AppModule phình ra

Tuần đầu, AppModule có 3 component. Tháng thứ ba nó có 40 declarations, 15 imports, 12 providers. Mỗi lần build lại toàn bộ. Mỗi lần mở file phải cuộn 200 dòng. Và không ai dám xoá dòng nào vì không biết ai còn dùng.

Tệ hơn: người dùng vào trang chủ nhưng vẫn phải tải code của trang Admin — thứ 99% người dùng không bao giờ mở.

🤔 Trước khi nhìn lời giải

Câu hỏi phân loại không phải "file này là gì?" mà là "thứ này cần tồn tại bao nhiêu bản, và tải lúc nào?" Trả lời được câu đó là tự suy ra được ba loại module.

3. CoreModule và cơ chế tự vệ

TypeScript · src/app/core/core.module.ts 
import { NgModule, Optional, SkipSelf } from '@angular/core';
import { provideHttpClient, withInterceptorsFromDi } from '@angular/common/http';
import { API_CONFIG } from './tokens/api-config.token';

@NgModule({
  providers: [
    // Angular 22: HttpClientModule đã DEPRECATED -> dùng provideHttpClient.
    // withInterceptorsFromDi() giữ cho class-based interceptor (Bài 24) vẫn chạy.
    provideHttpClient(withInterceptorsFromDi()),
    { provide: API_CONFIG, useValue: { baseUrl: '/api', pageSize: 12 } },
  ],
})
export class CoreModule {
  // @Optional()  -> lần import ĐẦU TIÊN, parentModule là null. Không có nó sẽ ném
  //                 NullInjectorError ngay lần đầu, tức là guard tự giết chính nó.
  // @SkipSelf()  -> bỏ qua injector của CHÍNH CoreModule, chỉ hỏi injector CHA.
  //                 Không có nó, nó luôn tự tìm thấy mình -> LÚC NÀO cũng ném lỗi.
  constructor(@Optional() @SkipSelf() parentModule: CoreModule | null) {
    if (parentModule) {
      throw new Error('CoreModule đã được import rồi. Chỉ import DUY NHẤT ở AppModule.');
    }
  }
}
🔎 Hai decorator, bỏ cái nào cũng hỏng
Bỏ điHậu quả
Bỏ @Optional()Lần import đầu tiên đã ném NullInjectorError — app không chạy được lần nào.
Bỏ @SkipSelf()Angular tìm thấy chính instance đang tạo → luôn có parentModule → luôn ném lỗi.

Cặp này là một ứng dụng trực tiếp của injector tree ở Bài 07: "hỏi lên trên, và chấp nhận câu trả lời rỗng".

🔥 Vì sao import 2 lần lại nguy hiểm

Nếu một lazy module lỡ imports: [CoreModule], nó tạo EnvironmentInjector riêng → có bản thứ hai của mọi service trong Core. Người dùng đăng nhập ở bản A, trang lazy đọc bản B thấy null. Không lỗi, không cảnh báo — chỉ là "tự nhiên bị đăng xuất khi vào trang Admin".

Với HTTP_INTERCEPTORS (multi: true) thì tệ hơn: interceptor chạy hai lần cho mỗi request.

4. SharedModule — exports mới là thứ có ích

TypeScript · src/app/shared/shared.module.ts 
@NgModule({
  declarations: [VndPipe],       // khai báo: pipe này THUỘC module này
  imports: [CommonModule],
  // exports = thứ DUY NHẤT khiến SharedModule có ích.
  // Không export thì module khác import vào cũng KHÔNG dùng được gì.
  // Re-export CommonModule để feature module khỏi phải tự import (*ngIf, *ngFor).
  exports: [CommonModule, VndPipe],
})
export class SharedModule {}
🔥 SharedModule KHÔNG được có providers

Đây là hệ quả trực tiếp của Bài 07. SharedModule được import vào mọi feature module, kể cả lazy. Mỗi lazy module có EnvironmentInjector riêng → mỗi cái nhận một bản service riêng.

Bạn tưởng đang dùng chung một CartService, thực tế trang Cart và trang Checkout có hai giỏ hàng khác nhau. Service singleton luôn thuộc về Core (hoặc providedIn: 'root'), không bao giờ thuộc Shared.

5. Feature module — tách theo nghiệp vụ

TypeScript · src/app/features/courses/courses.module.ts 
@NgModule({
  declarations: [CourseListComponent],
  imports: [SharedModule, CoursesRoutingModule],
  // KHÔNG có exports: không ai import feature module cả — router tự nạp nó.
})
export class CoursesModule {}
TypeScript · courses-routing.module.ts — forChild, KHÔNG phải forRoot 
const routes: Routes = [{ path: '', component: CourseListComponent }];

@NgModule({
  // forRoot() CHỈ gọi MỘT lần ở AppRoutingModule — nó dựng Router service.
  // Feature module dùng forChild(): chỉ ĐĂNG KÝ thêm route vào Router đã có.
  imports: [RouterModule.forChild(routes)],
  exports: [RouterModule],
})
export class CoursesRoutingModule {}
⚖️ Gọi forRoot() hai lần thì sao?

Bạn có hai bản Router đánh nhau: URL đổi nhưng view không đổi, hoặc điều hướng chạy hai lần. Quy tắc: forRoot() đúng một lần ở gốc, mọi nơi khác dùng forChild(). Cùng một triết lý với guard của CoreModule — chỉ khác là Router không tự bảo vệ giúp bạn.
