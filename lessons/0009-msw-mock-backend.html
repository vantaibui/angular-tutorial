Cắm MSW — giả lập backend ở tầng mạng

Chặn request ở Service Worker để HttpClient tưởng đang nói chuyện với server thật — code app không có một dòng nào biết mình đang dùng mock.

⏱ ~45 phút · 🎯 GET /api/courses trả data thật trong Network tab · 🏷️ EduCommerce

🎯 Sau bài này bạn phải làm được
  • Giải thích MSW chặn ở tầng nào, và vì sao điều đó khiến code app không cần đổi khi có backend thật.
  • Viết handler có phân trang, lọc, và trả lỗi 404 đúng shape.
  • Test chính logic handler bằng msw/node — không cần mở browser.
  • Chỉ bật mock ở dev, không để lọt vào build production.
🌉 Bắc cầu từ cái bạn đã biết

Bài 08 bạn dựng xong bộ khung nhưng CourseListComponent chưa có dữ liệu. Bài 01 bạn đã biết HttpClient trả về Observable huỷ được.

Bài này chỉ thêm một mảnh mới: đặt thứ giả lập THẤP HƠN HttpClient, để không code nào của app phải biết.

1. Bài toán thật: mock ở sai tầng thì phải viết lại

Cách hay gặp nhất — và cái giá của nó:

Vấn đề không phải "mock là xấu" mà là mock đặt sai tầng. Nếu chặn được ở chỗ thấp hơn HttpClient, mọi nhược điểm trên biến mất.

3. Cài đặt — và hai cái bẫy pnpm

bash · bước 1 — cài gói 
pnpm add -D msw@2
🔥 Bẫy 1: pnpm chặn postinstall của msw

Ngay sau lệnh trên bạn sẽ thấy:

lỗi thật 
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: msw@2.15.0

Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.

Đây không phải lỗi — là tính năng bảo mật. Từ pnpm 10, mọi postinstall của dependency bị chặn mặc định, vì đó là đường tấn công supply-chain kinh điển: gói bị chiếm quyền chạy script tuỳ ý trên máy bạn ngay lúc cài.

Hậu quả kèm theo: mọi lệnh pnpm exec đều bị chặn chừng nào còn gói chờ duyệt — kể cả pnpm exec tsc.

bash · bước 2 — duyệt CÓ CHỌN LỌC 
# Chỉ đích danh msw. TRÁNH `--all` — nó duyệt mù mọi gói, mất luôn ý nghĩa của lớp bảo vệ.
pnpm approve-builds msw

Lệnh này ghi lựa chọn vào pnpm-workspace.yaml. Sau đó Angular CLI cũng sẽ hỏi duyệt vài gói của nó — chúng không cần thiết (app vẫn build/test/serve bình thường khi bị chặn), nên hãy từ chối tường minh để pnpm thôi hỏi lại:

YAML · pnpm-workspace.yaml 
# pnpm chặn postinstall theo mặc định (chống supply-chain attack).
# Phải quyết định TỪNG gói một cách tường minh.
allowBuilds:
  msw: true                 # cần: msw init sinh file service worker
  esbuild: false             # không cần: đã có binary tiền biên dịch theo nền tảng
  lmdb: false                # không cần: chỉ là cache tuỳ chọn của Angular CLI
  msgpackr-extract: false    # không cần: tăng tốc tuỳ chọn cho lmdb
  "@parcel/watcher": false  # không cần: Angular có watcher dự phòng
⚖️ Đừng tin blog cũ về key cấu hình này

Nhiều bài viết bảo dùng onlyBuiltDependencies trong package.json. Tôi đã thử cả hai cách đó trên pnpm 11.13.1 và đều không ăn. Key đúng ở bản này là allowBuilds (dạng map) trong pnpm-workspace.yaml — tôi tìm ra bằng cách chạy pnpm approve-builds msw rồi xem nó ghi vào đâu. Mẹo này luôn đúng kể cả khi pnpm đổi key lần nữa.

4. Viết handlers

Copy mock-data/ vào src/mock-data/, rồi bật đọc JSON trong tsconfig.json:

JSON · tsconfig.json → compilerOptions 
"resolveJsonModule": true
TypeScript · src/mocks/handlers.ts 
import { http, HttpResponse } from 'msw';
import coursesJson from '../mock-data/courses.json';
import { Course, ApiListResponse } from '../app/core/models/types';

const courses = coursesJson as Course[];

// Generic! Phân trang không quan tâm T là gì — đúng bài học Bài 05.
function paginate<T>(items: T[], page: number, limit: number): ApiListResponse<T> {
  const start = (page - 1) * limit;
  return {
    data: items.slice(start, start + limit),
    meta: { page, limit, total: items.length, totalPages: Math.ceil(items.length / limit) },
  };
}

export const handlers = [
  // Dấu * ở đầu: khớp MỌI origin. Xem bẫy 2 bên dưới.
  http.get('*/api/courses', ({ request }) => {
    const url = new URL(request.url);
    const page = Number(url.searchParams.get('page') ?? 1);
    const limit = Number(url.searchParams.get('limit') ?? 12);
    const search = (url.searchParams.get('search') ?? '').toLowerCase();

    let ketQua = courses;
    if (search) ketQua = ketQua.filter((c) => c.title.toLowerCase().includes(search));

    return HttpResponse.json(paginate(ketQua, page, limit));
  }),

  http.get('*/api/courses/:id', ({ params }) => {
    const found = courses.find((c) => c.id === params['id']);
    if (!found) {
      // Trả đúng shape ApiErrorResponse trong types.ts — để Bài 24 bắt lỗi thật.
      return HttpResponse.json({ message: 'Không tìm thấy khoá học', statusCode: 404 }, { status: 404 });
    }
    return HttpResponse.json(found);
  }),
];
🔥 Bẫy 2: '/api/courses' chạy ở browser nhưng CHẾT ở test

Viết http.get('/api/courses') — trong browser chạy ngon, vì path tương đối tự resolve theo origin của trang. Nhưng khi test bằng msw/node thì không có origin nào cả, handler không khớp, và bạn nhận:

lỗi thật khi test 
[MSW] Error: intercepted a request without a matching request handler:
  • GET http://localhost/api/courses

Sửa bằng '*/api/courses' — dấu * khớp mọi origin, chạy đúng ở cả browser lẫn node. Viết như vậy ngay từ đầu.

5. Bật MSW — chỉ ở dev

TypeScript · src/mocks/browser.ts 
import { setupWorker } from 'msw/browser';
import { handlers } from './handlers';

export const worker = setupWorker(...handlers);
TypeScript · src/main.ts 
import { isDevMode } from '@angular/core';
import { platformBrowser } from '@angular/platform-browser';
import { AppModule } from './app/app.module';

async function bootstrap() {
  // isDevMode() là API chính chủ Angular, false sau khi build production.
  if (isDevMode()) {
    // import() ĐỘNG: MSW nằm ở chunk riêng, không vào bundle chính.
    const { worker } = await import('./mocks/browser');
    // 'bypass': request không khớp handler nào (file .js, ảnh...) đi thẳng ra mạng
    // thay vì bị MSW cảnh báo ầm ĩ trong console.
    await worker.start({ onUnhandledRequest: 'bypass' });
  }

  // await để lỗi bootstrap được .catch() bên dưới bắt.
  await platformBrowser().bootstrapModule(AppModule);
}

bootstrap().catch((err) => console.error(err));
⚖️ Nói thật: MSW vẫn bị đóng gói vào bản build production

isDevMode() được kiểm lúc chạy, không phải lúc build. Nên pnpm build vẫn sinh ra chunk chứa MSW (~330 kB) — nó không bao giờ được tải vì nhánh if không chạy, nhưng file vẫn nằm trong dist/.

Với dự án học tập thì chấp nhận được. Với production thật, cách sạch là dùng file replacement của Angular (environment.ts ↔ environment.prod.ts) để trình biên dịch loại hẳn nhánh đó. Tôi nêu ra vì biết một giải pháp có giới hạn gì quan trọng hơn là dùng nó mà tưởng nó hoàn hảo.

6. Test handler mà không cần browser

Service Worker chỉ chạy trong browser. Nhưng logic handler — phân trang, lọc, 404 — thì test được bằng msw/node, và nên test:

TypeScript · src/playground/msw-handlers.spec.ts 
import { setupServer } from 'msw/node';
import { handlers } from '../mocks/handlers';

// Cùng bộ handlers, khác "cổng cắm": browser dùng setupWorker, node dùng setupServer.
const server = setupServer(...handlers);
beforeAll(() => server.listen({ onUnhandledRequest: 'error' }));
afterAll(() => server.close());

const BASE = 'http://localhost';

it('phân trang: page=1 và page=2 KHÁC nhau', async () => {
  const p1 = await (await fetch(`${BASE}/api/courses?page=1&limit=5`)).json();
  const p2 = await (await fetch(`${BASE}/api/courses?page=2&limit=5`)).json();
  expect(p1.data).toHaveLength(5);
  expect(p1.data[0].id).not.toBe(p2.data[0].id);
});
🔎 Vì sao đây là cách test đúng

onUnhandledRequest: 'error' khiến test đỏ nếu có request nào không khớp handler. Nhờ vậy nó bắt được đúng bẫy 2 ở mục 4 — thay vì bạn phát hiện lúc chạy app rồi ngồi đoán.

🧩 Hint ladder — chỉ mở khi bị stuck

Hint 1 · Hướng suy nghĩ:
Handler chỉ là một hàm (request) => response. Mọi thứ khác — phân trang, lọc — là JavaScript thuần trên mảng. Đừng nghĩ nó phức tạp hơn thực tế.

Hint 2 · API cần dùng:
http.get(pattern, resolver) · HttpResponse.json(body, { status }) · new URL(request.url).searchParams.get('x') · params['id'] cho route param · setupWorker (browser) vs setupServer (node).

Hint 3 · Nếu TC6 không thấy request:
Kiểm theo thứ tự: (1) DevTools → Application → Service Workers có mockServiceWorker.js đang activated không; (2) console có dòng [MSW] Mocking enabled không; (3) đã hard reload chưa — Service Worker cần đăng ký lại sau khi đổi file.
