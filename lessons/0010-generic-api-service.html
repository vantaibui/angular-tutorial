GenericApiService<T> — Generics vào việc thật

Một lớp CRUD dùng chung cho mọi entity — và vì sao lớp cơ sở không được gắn @Injectable.

⏱ ~40 phút · 🎯 CRUD viết một lần, type-safe tuyệt đối · 🏷️ EduCommerce · tầng service

🎯 Sau bài này bạn phải làm được
  • Viết lớp cơ sở generic cho HTTP, và giải thích vì sao nó phải là abstract.
  • Dùng Omit<T,'id'> cho create và Partial<T> cho update — và nói được vì sao.
  • Truyền query param an toàn bằng HttpParams.
  • Test service HTTP bằng HttpTestingController mà không cần server.
🌉 Bắc cầu từ cái bạn đã biết

Bài 06 bạn viết InMemoryRepository<T extends {id: string}> với findById trả T | undefined và update nhận Partial<T>. Bài 09 bạn có backend giả trả JSON thật.

Bài này chỉ thêm một mảnh mới: cùng cấu trúc đó, nhưng nguồn dữ liệu là HTTP nên mọi thứ trả về Observable.

1. Bài toán thật: sáu service, một logic

EduCommerce có Course, User, Review, Enrollment, Category, Coupon. Viết riêng từng service thì mỗi cái ~40 dòng CRUD giống hệt nhau — 240 dòng, và sửa một bug phải sửa sáu chỗ.

Nhưng viết một service dùng chung trả any thì mất sạch type-safety: courseService.getById('x') lẽ ra phải trả Course.

🤔 Trước khi nhìn lời giải

Đây đúng là bài toán Bài 05 đặt ra: viết một lần mà mỗi chỗ dùng vẫn giữ kiểu riêng. Câu hỏi mới duy nhất: lớp cơ sở cần HttpClient và một endpoint — làm sao đưa hai thứ đó vào khi mỗi service con có endpoint khác nhau?

2. Mental model: lớp cơ sở KHÔNG phải một service

Đây là điểm dễ sai nhất bài. Trực giác bảo "nó là service thì gắn @Injectable". Nhưng hãy hỏi: Angular sẽ tiêm endpoint nào vào nó?

Vì sao lớp cơ sở phải abstract 
// ❌ Nếu gắn @Injectable({providedIn:'root'}) lên lớp cơ sở:
//    Angular sẽ cố tự tạo GenericApiService — nhưng endpoint là gì? Không ai biết.
//    Nó KHÔNG phải một dịch vụ cụ thể, chỉ là KHUÔN để đúc ra dịch vụ.

// ✅ abstract: nói với TypeScript "không được new trực tiếp",
//    và không đăng ký gì vào DI. Chỉ lớp CON mới là service thật.
export abstract class GenericApiService<T extends { id: string }> { ... }
💡 Hãy giữ câu này trong đầu

Lớp cơ sở là cái khuôn, không phải cái bánh. Chỉ thứ có endpoint cụ thể mới đáng được DI biết tới.

3. Viết GenericApiService<T>

TypeScript · src/app/core/services/generic-api.service.ts 
import { HttpClient, HttpParams } from '@angular/common/http';
import { Observable } from 'rxjs';
import { ApiListResponse } from '../models/types';

/**
 * CRUD dùng chung cho MỌI entity có `id: string`.
 * KHÔNG @Injectable — đây là lớp CƠ SỞ, không tự đăng ký vào DI.
 */
export abstract class GenericApiService<T extends { id: string }> {

  // protected: lớp con dùng được, code ngoài thì không.
  protected constructor(
    protected readonly http: HttpClient,
    /** Endpoint riêng của từng entity, vd '/api/courses'. */
    protected readonly endpoint: string,
  ) {}

  getAll(params: Record<string, string | number> = {}): Observable<ApiListResponse<T>> {
    // HttpParams BẤT BIẾN: mỗi .set() trả về object MỚI.
    // Viết httpParams.set(...) mà không gán lại là mất sạch param — bẫy kinh điển.
    let httpParams = new HttpParams();
    for (const [k, v] of Object.entries(params)) {
      httpParams = httpParams.set(k, String(v));
    }
    // http.get<X> chính là generic function do Angular viết sẵn (Bài 05).
    return this.http.get<ApiListResponse<T>>(this.endpoint, { params: httpParams });
  }

  getById(id: string): Observable<T> {
    return this.http.get<T>(`${this.endpoint}/${id}`);
  }

  // Omit<T,'id'>: người gọi KHÔNG được truyền id — server sinh.
  // Kiểu chính là tài liệu: chữ ký tự nói ra hợp đồng thật của method.
  create(data: Omit<T, 'id'>): Observable<T> {
    return this.http.post<T>(this.endpoint, data);
  }

  // Partial<T>: patch vài field vẫn hợp lệ, nhưng field LẠ vẫn bị chặn.
  update(id: string, patch: Partial<T>): Observable<T> {
    return this.http.patch<T>(`${this.endpoint}/${id}`, patch);
  }

  remove(id: string): Observable<void> {
    return this.http.delete<void>(`${this.endpoint}/${id}`);
  }
}

4. Happy path chưa đủ

🔥 HttpParams là bất biến — và im lặng khi bạn quên
TypeScript 
// ❌ SAI: .set() trả object MỚI, dòng này vứt kết quả đi.
let p = new HttpParams();
p.set('page', '2');          // p vẫn RỖNG

// ✅ ĐÚNG: gán lại
p = p.set('page', '2');

Không lỗi, không cảnh báo — chỉ là request thiếu param, server trả trang 1, và bạn đi tìm bug ở phía backend. Cùng triết lý bất biến với {...cũ, ...patch} ở Bài 06.

⚖️ Vì sao dùng HttpParams chứ không nối chuỗi

Nối chuỗi `?search=${term}` vỡ ngay khi người dùng gõ dấu &, khoảng trắng, hay tiếng Việt có dấu. HttpParams tự encode. Với ô tìm kiếm khoá học tiếng Việt, đây sẽ xảy ra.

5. Test service HTTP mà không cần server

Angular có sẵn công cụ giả lập tầng HTTP backend — khác MSW (Bài 09) ở chỗ nó chặn ngay dưới HttpClient, không cần Service Worker:

TypeScript · src/playground/module2.spec.ts 
import { provideHttpClient } from '@angular/common/http';
import { HttpTestingController, provideHttpClientTesting } from '@angular/common/http/testing';

beforeEach(() => {
  TestBed.configureTestingModule({
    providers: [provideHttpClient(), provideHttpClientTesting()],
  });
  httpMock = TestBed.inject(HttpTestingController);
  courseService = TestBed.inject(CourseService);
});

it('getAll truyền query params đúng', async () => {
  // Observable LAZY (Bài 03): phải subscribe thì request mới bay đi.
  // firstValueFrom() vừa subscribe vừa cho ta await kết quả.
  const p = firstValueFrom(courseService.getAll({ page: 2, search: 'ang' }));

  const req = httpMock.expectOne((r) => r.url === '/api/courses');
  expect(req.request.params.get('page')).toBe('2');
  expect(req.request.params.get('search')).toBe('ang');

  req.flush({ data: [], meta: { page: 2, limit: 12, total: 0, totalPages: 0 } });
  await p;
  httpMock.verify();   // đỏ nếu còn request nào chưa được xử lý
});
🔥 Bẫy tôi tự đâm vào khi soạn bài này

Test đầu tiên tôi viết courseService.create(u); rồi httpMock.expectOne(...) — và nhận:

lỗi thật 
Error: Expected one matching request for criteria
"Match URL: /api/courses", found none.

Nguyên nhân: Observable lazy (Bài 03). Không subscribe() thì HttpClient không gửi gì cả. Đây là lý do Bài 03 dạy lazy/eager trước bài này — và là bug bạn sẽ gặp lại mỗi khi "gọi API mà Network tab trống".

🎤 Góc phỏng vấn

Hỏi: "HttpTestingController và MSW khác nhau thế nào?"

Trả lời gọn: "HttpTestingController chặn ngay dưới HttpClient, trong tiến trình test — nhanh, tất định, hợp cho unit test service. MSW chặn ở tầng mạng qua Service Worker (browser) hoặc interceptor của Node — chậm hơn nhưng thật hơn, và cùng một bộ handler dùng được cho cả app đang chạy lẫn e2e. Thực tế dùng cả hai: HttpTestingController cho unit test, MSW cho dev và e2e."

7. Câu hỏi tư duy

Lớp cơ sở cần HttpClient. Nhưng constructor của nó là protected và nhận HttpClient làm tham số — nghĩa là lớp con phải truyền vào.

Lớp con lấy HttpClient ở đâu? Nếu bạn viết constructor(http: HttpClient) { super(http, '/api/courses'); } thì mỗi lớp con phải khai lại tham số đó. Có 6 entity là lặp 6 lần một dòng chẳng mang thông tin gì.

Có cách nào để lớp con chỉ cần khai đúng thứ riêng của nó — cái endpoint?
