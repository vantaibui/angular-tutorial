Class-based AuthGuard implements CanActivate

Chặn route trước khi component kịp tồn tại — và vì sao trả UrlTree tốt hơn gọi navigate() rồi return false.

⏱ ~40 phút · 🎯 Chặn đúng, redirect kèm returnUrl · 🏷️ EduCommerce · Auth

🎯 Sau bài này bạn phải làm được
  • Viết guard dạng class — cú pháp bạn sẽ gặp ở mọi codebase Angular cũ.
  • Giải thích vì sao trả UrlTree tốt hơn navigate() + false.
  • Giữ returnUrl đúng, kể cả khi URL gốc có query string.
  • Test guard bằng điều hướng Router thật, không chỉ gọi hàm.
🌉 Bắc cầu từ cái bạn đã biết

Bài 12 kết bằng câu hỏi: chặn ở ngOnInit thì component đã dựng, chunk đã tải, trang đã loé lên. Bài 07 bạn biết Angular tự inject class qua DI.

Bài này chỉ thêm một mảnh mới: Router có một điểm móc chạy TRƯỚC khi route được kích hoạt — và bạn cắm một class vào đó.

Guard là câu hỏi Router đặt ra trước khi tốn bất kỳ công sức nào. ngOnInit là lúc công sức đã tốn xong.

3. Viết AuthGuard

TypeScript · src/app/core/guards/auth.guard.ts 
import { Injectable, inject } from '@angular/core';
import {
  ActivatedRouteSnapshot, CanActivate, Router, RouterStateSnapshot, UrlTree,
} from '@angular/router';
import { AuthService } from '../services/auth.service';

// providedIn:'root' -> Router tự inject được khi gặp canActivate: [AuthGuard]
@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {
  private readonly auth = inject(AuthService);
  private readonly router = inject(Router);

  // route: thông tin TĨNH của route (data, params) — Bài 14 sẽ dùng.
  // state: trạng thái điều hướng, state.url là URL người dùng ĐỊNH vào.
  canActivate(_route: ActivatedRouteSnapshot, state: RouterStateSnapshot): boolean | UrlTree {
    if (this.auth.isLoggedIn) return true;

    // Trả UrlTree thay vì navigate() rồi return false — xem mục 4.
    return this.router.createUrlTree(['/login'], {
      queryParams: { returnUrl: state.url },
    });
  }
}
TypeScript · gắn vào route 
{
  path: 'dashboard',
  // canActivate nhận CLASS — Angular tự inject qua DI (Bài 07).
  // Modern (v15+) dùng CanActivateFn dạng hàm — Bài 55 sẽ migrate.
  canActivate: [AuthGuard],
  loadChildren: () => import('./features/dashboard/dashboard.module').then((m) => m.DashboardModule),
}
⚖️ Class guard có còn dùng được ở Angular 22 không?

Có. Tôi đã tra API docs: interface CanActivate vẫn ở trạng thái stable, không deprecated. Angular từng đánh dấu deprecated ở v15.2 rồi rút lại sau phản hồi cộng đồng.

Và tôi đã verify bằng test điều hướng thật trên v22.1.4 — canActivate: [AuthGuard] với class chạy đúng. Nên bạn học cú pháp này là học thứ vừa dùng được hôm nay, vừa đọc được codebase v12–v16.

4. UrlTree vs navigate() + false

TypeScript · hai cách, một cách đúng hơn 
// ❌ Cách cũ: hai hành động rời rạc
if (!this.auth.isLoggedIn) {
  this.router.navigate(['/login']);   // bắt đầu điều hướng MỚI...
  return false;                        // ...trong khi cái cũ CHƯA huỷ xong
}

// ✅ Cách đúng: MỘT giá trị trả về, Router tự lo phần còn lại
return this.router.createUrlTree(['/login'], {
  queryParams: { returnUrl: state.url },
});

Điểm cuối là điều đáng giá nhất: UrlTree biến guard thành thứ mô tả ý định thay vì tự đi làm. Test chỉ cần so giá trị trả về — không cần dàn dựng spy nào.

5. Happy path chưa đủ

🔥 navigate() trả về true khi bị guard chặn

Đây là thứ tôi đoán sai khi viết test, và phải chạy mới biết:

TypeScript · kết quả đã verify trên Angular 22.1.4 
const ok = await router.navigate(['/dashboard']);   // chưa đăng nhập

expect(ok).toBe(true);        // ← TRUE, không phải false!
expect(router.url).toBe('/login?returnUrl=%2Fdashboard');

Vì redirect bằng UrlTree được tính là điều hướng thành công — chỉ là tới URL khác. Hệ quả thực tế: đừng dùng giá trị trả về của navigate() để biết mình có bị chặn hay không. Muốn biết đã tới đâu, kiểm router.url.

⚖️ returnUrl phải giữ nguyên query string

Người dùng đang ở /courses?page=2&search=ang thì hết phiên. Dùng state.url là lấy được toàn bộ URL kể cả query — và queryParams tự encode nên dấu & không cắt đôi tham số.

TypeScript · test đã verify 
const kq = guard.canActivate(snapshot(), state('/courses?page=2&search=ang'));
const url = router.serializeUrl(kq as UrlTree);

expect(decodeURIComponent(url.split('returnUrl=')[1]))
  .toBe('/courses?page=2&search=ang');   // nguyên vẹn

Nếu bạn tự nối chuỗi '/login?returnUrl=' + state.url thì dấu & trong URL gốc sẽ bị hiểu thành tham số mới, và returnUrl bị cắt cụt thành /courses?page=2.

6. Test guard bằng điều hướng THẬT

Gọi guard.canActivate(...) trực tiếp là test tốt và nhanh. Nhưng nó không chứng minh Router chấp nhận class guard của bạn. Nên làm cả hai tầng:

TypeScript · test điều hướng thật 
TestBed.configureTestingModule({
  declarations: [DashCmp, LoginCmp],
  providers: [
    provideRouter([
      { path: 'login', component: LoginCmp },
      { path: 'dashboard', component: DashCmp, canActivate: [AuthGuard] },
    ]),
    provideLocationMocks(),   // giả lập History API trong môi trường test
  ],
});

it('chưa đăng nhập -> Router CHẶN và đưa về /login', async () => {
  await router.navigate(['/dashboard']);
  expect(router.url).toBe('/login?returnUrl=%2Fdashboard');
});
🎤 Góc phỏng vấn

Hỏi: "Guard trả false và trả UrlTree khác gì nhau?"

Trả lời gọn: "false chỉ huỷ điều hướng — người dùng đứng nguyên trang cũ, không được thông báo gì. UrlTree vừa huỷ vừa nói cho Router biết đi đâu, gộp thành một chu kỳ điều hướng duy nhất nên không có race condition. false hợp khi thật sự muốn 'ở yên đó' — ví dụ guard canDeactivate hỏi 'bạn có chắc muốn rời form?'. Cần chuyển hướng thì luôn dùng UrlTree."

🧩 Hint ladder — chỉ mở khi bị stuck

Hint 1 · Hướng suy nghĩ:
Guard chỉ là một class có method canActivate trả về boolean | UrlTree. Không có gì huyền bí — test được như hàm thường.

Hint 2 · API cần dùng:
implements CanActivate · router.createUrlTree([path], { queryParams }) · state.url lấy URL đầy đủ · router.serializeUrl(urlTree) để so trong test · provideRouter([]) + provideLocationMocks() từ @angular/common/testing.

Hint 3 · Cách giả lập snapshot trong test:
Không cần dựng snapshot thật: const state = { url: '/dashboard' } as RouterStateSnapshot và const route = { data: {} } as unknown as ActivatedRouteSnapshot là đủ, vì guard chỉ đụng vào đúng hai field đó.

✅ Senior takeaway
  • Tôi biết guard chạy trước tải chunk và dựng component.
  • Tôi trả UrlTree thay vì navigate() + false, và giải thích được vì sao.
  • Tôi biết navigate() trả true khi bị redirect — không dùng nó để phát hiện chặn.
  • Tôi giữ returnUrl nguyên vẹn bằng queryParams, không nối chuỗi.
  • Tôi nhớ guard là bảo vệ client-side — bảo mật thật vẫn phải ở server.

8. Câu hỏi tư duy

AuthGuard chỉ trả lời được "đã đăng nhập chưa". Nhưng /dashboard chỉ dành cho admin và instructor, còn /admin/users thì chỉ admin.

Bạn có thể viết AdminGuard, InstructorGuard, AdminOrInstructorGuard… nhưng số guard sẽ nổ theo tổ hợp vai trò.
