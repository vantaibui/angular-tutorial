Bài 14 kết bằng câu hỏi: luật "hai mật khẩu phải khớp" sống ở đâu? Không ô nào nhìn thấy ô kia.

Bài này chỉ thêm một mảnh mới: form là cây, và validator gắn được ở BẤT KỲ nút nào của cây.

1. Bài toán thật: luật không thuộc về ô nào

Form đăng ký: email, password, confirmPassword. Hai luật đầu dễ — required, email, độ dài. Luật thứ ba thì khác: "password và confirmPassword phải khớp".

Gắn vào confirmPassword thì nó cần đọc giá trị của password — mà ValidatorFn chỉ nhận đúng một AbstractControl: chính nó.

🤔 Trước khi nhìn lời giải

Nếu control không thấy anh em của nó, thì thứ duy nhất thấy được cả hai là cha của chúng. Vậy validator nên gắn ở đâu?

💡 Hãy giữ câu này trong đầu

Validator gắn ở nút nào thì nhìn thấy đúng nút đó và con cháu. Cần so hai ô với nhau → gắn ở cha chung gần nhất.

🔥 Bẫy: lỗi ở group KHÔNG xuất hiện ở control con

Gắn validator ở group thì form.get('confirm').errors vẫn là null. Template hiển thị lỗi theo control sẽ không thấy gì — form invalid mà không báo lỗi nào, người dùng bấm Submit không được và không hiểu vì sao.

Phải đọc ở form.errors, hoặc cho validator tự gán lỗi xuống control con.

3. Viết validator

TypeScript · src/app/core/validators/cross-field.validator.ts 
export function matchFields(fieldA: string, fieldB: string): ValidatorFn {
  // Trả về HÀM -> tham số hoá được, dùng lại cho email/confirmEmail...
  return (group: AbstractControl): ValidationErrors | null => {
    const a = group.get(fieldA);
    const b = group.get(fieldB);
    if (!a || !b) return null;

    // Chưa nhập gì thì CHƯA phải lỗi "không khớp" — để required lo việc đó.
    // Không có dòng này, form vừa mở đã đỏ lòm.
    if (!b.value) return null;

    // null = HỢP LỆ. Object = LỖI. Ngược trực giác nhưng là quy ước của Angular.
    return a.value === b.value ? null : { fieldsMismatch: { fieldA, fieldB } };
  };
}
TypeScript · validator trả về THÔNG TIN, không chỉ true 
export function strongPassword(): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null => {
    const v = (control.value ?? '') as string;
    if (!v) return null;

    const loi: string[] = [];
    if (v.length < 8) loi.push('doDai');
    if (!/[A-Z]/.test(v)) loi.push('chuHoa');
    if (!/[a-z]/.test(v)) loi.push('chuThuong');
    if (!/[0-9]/.test(v)) loi.push('so');

    // Trả DANH SÁCH thiếu gì -> template nói được "còn thiếu chữ hoa và số"
    // thay vì "mật khẩu không hợp lệ" (vô dụng với người dùng).
    return loi.length ? { strongPassword: { thieu: loi } } : null;
  };
}
🔎 Payload của lỗi là thứ phân biệt form tốt và form tệ

{ required: true } đủ vì chỉ có một cách sai. Nhưng mật khẩu có bốn cách sai — trả về danh sách cụ thể để UI hướng dẫn được người dùng sửa đúng chỗ. Test đã verify: nhập 'abc' ra thieu: ['doDai', 'chuHoa', 'so'].

4. Ráp vào form

TypeScript · register.component.ts 
private readonly fb = inject(FormBuilder);

form = this.fb.group(
  {
    email: ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, strongPassword()]],
    confirm: ['', Validators.required],
  },
  // Tham số THỨ HAI của fb.group() = options của chính GROUP.
  // Đặt nhầm vào trong object thứ nhất là tạo một control tên "validators".
  { validators: matchFields('password', 'confirm') },
);

5. Happy path chưa đủ

🔥 value bỏ qua control bị disable

form.value không chứa control đang disabled. Bạn disable ô role cho người dùng thường, submit lên server thiếu hẳn field đó, và backend báo lỗi validation khó hiểu.

Dùng form.getRawValue() khi cần toàn bộ giá trị kể cả ô disabled.

⚖️ setValue vs patchValue

setValue đòi đủ mọi field, thiếu một cái là ném lỗi — an toàn khi bạn muốn chắc chắn không sót. patchValue nhận một phần, im lặng bỏ qua khoá lạ — tiện nhưng gõ sai tên field thì không ai báo.

🎤 Góc phỏng vấn

Hỏi: "Cross-field validator đặt ở đâu, vì sao?"

Trả lời gọn: "Ở FormGroup chứa cả hai control, vì ValidatorFn chỉ nhận đúng control mà nó gắn vào — control con không thấy anh em. Hệ quả cần nhớ: lỗi nằm ở form.errors chứ không ở form.get('confirm').errors, nên template phải đọc đúng chỗ, nếu không form invalid mà chẳng hiện lỗi nào."

7. Câu hỏi tư duy

Form Review cần chọn số sao. Không có thẻ HTML nào làm việc đó — bạn phải tự vẽ 5 ngôi sao bằng <button>.

Bạn có thể để component phát @Output() ratingChange rồi component cha tự form.get('rating').setValue(...). Nó chạy. Nhưng khi form gọi disable(), component sao của bạn không biết gì — vẫn bấm được. Và form.reset() cũng không xoá được số sao.
