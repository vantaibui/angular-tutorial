1. Bản đầy đủ

TypeScript · src/app/shared/form-controls/rating-input.component.ts 
@Component({
  selector: 'app-rating-input',
  standalone: false,
  template: `
    <div class="rating" role="radiogroup">
      @for (sao of saoList; track sao) {
        <button
          type="button"                        <!-- KHÔNG có: bấm sao sẽ SUBMIT form -->
          class="star"
          [class.active]="sao <= value"
          [disabled]="isDisabled"
          role="radio"
          [attr.aria-checked]="sao === value"
          (click)="chon(sao)"
          (blur)="onTouched()"
        >★</button>
      }
    </div>
  `,
  providers: [{
    provide: NG_VALUE_ACCESSOR,
    useExisting: forwardRef(() => RatingInputComponent),
    multi: true,
  }],
})
export class RatingInputComponent implements ControlValueAccessor {
  @Input() max = 5;

  // Angular 22 zoneless: form đẩy giá trị xuống thì không có event nào
  // để kích hoạt change detection -> phải tự báo (Bài 16 mục 5).
  private readonly cdr = inject(ChangeDetectorRef);

  value = 0;
  isDisabled = false;

  get saoList(): number[] {
    return Array.from({ length: this.max }, (_, i) => i + 1);
  }

  // Khởi tạo rỗng -> không phải kiểm null mỗi lần gọi.
  // Angular LUÔN gọi register* trước khi dùng, nhưng test thì có thể không.
  private onChange: (v: number) => void = () => {};
  onTouched: () => void = () => {};   // public: template gọi được ở (blur)

  // ① Form -> component
  writeValue(value: number | null): void {
    this.value = value ?? 0;   // reset() truyền null -> phải chịu được
    this.cdr.markForCheck();
  }

  // ② + ③ Angular trao callback, ta cất đi
  registerOnChange(fn: (v: number) => void): void { this.onChange = fn; }
  registerOnTouched(fn: () => void): void { this.onTouched = fn; }

  // ④ Form -> component
  setDisabledState(isDisabled: boolean): void {
    this.isDisabled = isDisabled;
    this.cdr.markForCheck();
  }

  chon(sao: number): void {
    // Chốt chặn thứ hai: [disabled] lo phần UI, dòng này lo phần logic.
    // Cần cả hai vì click có thể tới từ code, không chỉ từ chuột.
    if (this.isDisabled) return;

    this.value = sao;
    this.onChange(sao);   // báo LÊN form
    this.onTouched();     // bấm = đã tương tác
  }
}
🔥 type="button" — thiếu là form tự submit

Mặc định <button> trong <form> có type="submit". Bấm chọn sao sẽ gửi form. Bug này rất hay gặp và cực khó đoán, vì triệu chứng là "trang tự reload khi tôi chấm sao".

2. onTouched gọi lúc nào? — câu hỏi tư duy Bài 16

Tôi chọn gọi ở cả hai chỗ, có lý do:

Gọi ởVì sao
(blur) trên mỗi nútNgười dùng lướt qua rồi bỏ đi mà không chọn → vẫn tính là đã xem. Giống hệt <input>.
Trong chon()Bấm là tương tác rõ ràng nhất. Không đợi blur mới báo — nếu đây là ô cuối form thì blur có thể không bao giờ xảy ra.
⚖️ Chỉ dùng (blur) thì có lỗ

Rating là ô cuối, người dùng bấm 4 sao rồi bấm thẳng Submit. Nút Submit lấy focus → blur có xảy ra. Nhưng nếu họ bấm sao rồi dùng phím tắt gửi form, hoặc form tự submit khi đủ điều kiện, thì touched vẫn false và thông báo lỗi liên quan sẽ không hiện. Gọi ở cả hai chỗ là rẻ và bịt được lỗ đó.

3. Test — chứng minh từng method

TypeScript · host component để test trong FormGroup THẬT 
@Component({
  standalone: false,
  template: `
    <form [formGroup]="form">
      <app-rating-input formControlName="rating"></app-rating-input>
    </form>
  `,
})
class HostComponent {
  form: FormGroup;
  constructor(fb: FormBuilder) { this.form = fb.group({ rating: [0] }); }
}

// ⚠️ Component dùng trong test PHẢI thuộc một NgModule lúc BIÊN DỊCH.
// Khai qua TestBed.declarations là quá muộn — trình biên dịch template
// không thấy được và báo "'app-rating-input' is not a known element".
@NgModule({ declarations: [HostComponent], imports: [FormControlsModule] })
class TestHostModule {}
TypeScript · 5 test, mỗi test một method (đã verify xanh) 
it('writeValue: form.setValue -> UI cập nhật', () => {
  host.form.get('rating')!.setValue(4);
  fixture.detectChanges();
  expect(stars().filter((b) => b.classList.contains('active'))).toHaveLength(4);
});

it('registerOnChange: bấm sao -> form nhận giá trị', () => {
  stars()[2].click();
  fixture.detectChanges();
  expect(host.form.get('rating')!.value).toBe(3);
});

it('registerOnTouched: chưa chạm untouched, chạm rồi touched', () => {
  expect(host.form.get('rating')!.touched).toBe(false);
  stars()[0].click();
  fixture.detectChanges();
  expect(host.form.get('rating')!.touched).toBe(true);
});

it('setDisabledState: form.disable() -> nút disable THẬT', () => {
  host.form.get('rating')!.disable();
  fixture.detectChanges();
  expect(stars().every((b) => b.disabled)).toBe(true);
});

it('disable rồi bấm -> giá trị KHÔNG đổi', () => {
  host.form.get('rating')!.setValue(2);
  host.form.get('rating')!.disable();
  fixture.detectChanges();
  stars()[4].click();
  fixture.detectChanges();
  expect(host.form.get('rating')!.value).toBe(2);
});
🔎 Vì sao test qua DOM chứ không gọi thẳng method

Gọi cmp.writeValue(4) rồi expect(cmp.value).toBe(4) chỉ chứng minh bạn biết gán biến. Nó không chứng minh Angular tìm thấy accessor của bạn, hay UI thật sự đổi. Test qua FormGroup + DOM mới bắt được lỗi zoneless ở Bài 16 — và nó đã bắt được, khi tôi soạn bài này.
