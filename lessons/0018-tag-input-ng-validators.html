<app-tag-input> + NG_VALIDATORS

Control tự mang validator của nó — nơi dùng không phải khai gì thêm, nên không thể quên.

⏱ ~45 phút · 🎯 Chip input với luật max 5 tag · 🏷️ EduCommerce · form Course

🎯 Sau bài này bạn phải làm được
  • Viết CVA quản lý giá trị mảng, không chỉ giá trị đơn.
  • Dùng NG_VALIDATORS để control tự mang luật của nó.
  • Giải thích vì sao phải tạo mảng mới thay vì push.
  • Biết validator nội bộ chạy cả khi giá trị được set từ ngoài.
🌉 Bắc cầu từ cái bạn đã biết

Bài 17: CVA với giá trị number. Bài 07: multi: true gom nhiều provider thành mảng.

Bài này thêm hai mảnh: giá trị mảng, và control tự khai validator qua một multi token thứ hai.

1. Bài toán thật: luật đi lạc khỏi control

TypeScript · ❌ luật nằm ở nơi dùng 
// form tạo khoá học
tags: [[], [maxLengthArray(5)]],

// form sửa khoá học — ai đó quên
tags: [[]],

// form nhân bản khoá học — ai đó nhớ nhưng gõ 10
tags: [[], [maxLengthArray(10)]],

Ba nơi, ba luật khác nhau cho cùng một khái niệm. Không có gì báo lỗi. Sau đó backend từ chối bản ghi có 8 tag và không ai hiểu vì sao form cho qua.

🤔 Trước khi nhìn lời giải

<input type="email"> không bắt bạn khai luật email ở mọi form. Luật đi kèm control. Custom control của bạn cũng làm được điều đó — bằng đường nào?

💡 Hãy giữ câu này trong đầu

Luật thuộc về control, không thuộc về form dùng nó. Đăng ký qua NG_VALIDATORS thì nơi dùng không thể quên.

Cả hai đều là multi token — đúng cơ chế bạn học ở Bài 07 với HTTP_INTERCEPTORS. Angular gom tất cả validator (của control + của form khai thêm) thành một mảng và chạy hết.

3. Code

TypeScript · src/app/shared/form-controls/tag-input.component.ts 
@Component({
  selector: 'app-tag-input',
  standalone: false,
  template: `
    <div class="tag-input">
      @for (tag of tags; track tag) {
        <span class="chip">
          {{ tag }}
          <button type="button" [disabled]="isDisabled" (click)="xoa(tag)">×</button>
        </span>
      }
      <input
        [value]="nhap"
        [disabled]="isDisabled"
        (input)="nhap = $any($event.target).value"
        (keydown.enter)="them($event)"
        (blur)="onTouched()"
        placeholder="Nhập tag rồi Enter" />
    </div>
  `,
  providers: [
    { provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => TagInputComponent), multi: true },
    // Control TỰ mang validator -> nơi dùng không phải khai gì thêm.
    { provide: NG_VALIDATORS, useExisting: forwardRef(() => TagInputComponent), multi: true },
  ],
})
export class TagInputComponent implements ControlValueAccessor, Validator {
  @Input() maxTags = 5;

  private readonly cdr = inject(ChangeDetectorRef);   // zoneless (Bài 16)

  tags: string[] = [];
  nhap = '';
  isDisabled = false;

  private onChange: (v: string[]) => void = () => {};
  onTouched: () => void = () => {};

  writeValue(value: string[] | null): void {
    this.tags = value ?? [];   // null từ reset() -> mảng rỗng
    this.cdr.markForCheck();
  }
  registerOnChange(fn: (v: string[]) => void): void { this.onChange = fn; }
  registerOnTouched(fn: () => void): void { this.onTouched = fn; }
  setDisabledState(d: boolean): void { this.isDisabled = d; this.cdr.markForCheck(); }

  // Interface Validator — Angular gọi mỗi khi giá trị đổi, dù đổi từ đâu.
  validate(_control: AbstractControl): ValidationErrors | null {
    if (this.tags.length > this.maxTags) {
      // Payload có thông tin -> UI nói được "tối đa 5, bạn đang có 6" (Bài 15).
      return { maxTags: { max: this.maxTags, thucTe: this.tags.length } };
    }
    return null;
  }

  them(ev: Event): void {
    ev.preventDefault();       // Enter trong form = submit. Chặn.
    const t = this.nhap.trim();
    if (!t || this.isDisabled) return;
    if (this.tags.includes(t)) { this.nhap = ''; return; }   // chặn trùng

    // MẢNG MỚI, không push tại chỗ — xem mục 4.
    this.tags = [...this.tags, t];
    this.nhap = '';
    this.onChange(this.tags);
    this.onTouched();
  }

  xoa(tag: string): void {
    if (this.isDisabled) return;
    this.tags = this.tags.filter((x) => x !== tag);
    this.onChange(this.tags);
    this.onTouched();
  }
}

4. Vì sao mảng MỚI, không push

🔥 push giữ nguyên tham chiếu — mọi so sánh đều "không đổi"
TypeScript 
// ❌ cùng một object trước và sau
this.tags.push(t);
this.onChange(this.tags);

// ✅ object mới -> so sánh tham chiếu phát hiện được
this.tags = [...this.tags, t];
this.onChange(this.tags);

Với push, ba thứ hỏng cùng lúc:

  • OnPush change detection so tham chiếu → không vẽ lại (Bài 40).
  • distinctUntilChanged trên valueChanges nuốt luôn thay đổi (Bài 01).
  • Form cha giữ tham chiếu tới cùng mảng → so sánh "giá trị ban đầu vs hiện tại" để hỏi "bạn có muốn rời trang?" luôn nói "không đổi".

Cùng nguyên tắc bất biến với {...cũ, ...patch} ở Bài 06 và HttpParams ở Bài 10. Đây là chủ đề lặp lại xuyên suốt Angular.

5. Validator chạy cả khi set từ ngoài

TypeScript · test đã verify 
it('validator chạy CẢ KHI set từ ngoài, không chỉ khi gõ', () => {
  host.form.get('tags')!.setValue(['a','b','c','d','e','f']);
  fixture.detectChanges();
  expect(host.form.get('tags')!.errors?.['maxTags']).toBeTruthy();
});
🔎 Vì sao test này quan trọng

Dữ liệu bẩn không chỉ tới từ bàn phím. Nó tới từ API trả về bản ghi cũ có 8 tag, từ patchValue khi nhân bản khoá học. Nếu validator chỉ chạy lúc gõ, form sẽ báo valid cho dữ liệu sai và bạn gửi thẳng lên server.

Angular gọi validate() mỗi khi giá trị control đổi — bất kể đổi từ đâu. Đó là điều NG_VALIDATORS cho bạn miễn phí, còn validator khai ở form thì cũng vậy; khác biệt duy nhất là không thể quên khai.

⚖️ Giới hạn: @Input() maxTags đổi không tự chạy lại validator

Nếu maxTags đổi động lúc chạy, Angular không tự validate lại — nó không biết validator phụ thuộc vào input đó. Phải gọi control.updateValueAndValidity() thủ công trong ngOnChanges. Với EduCommerce thì maxTags cố định nên không cần, nhưng biết giới hạn này trước khi nó cắn bạn thì tốt hơn.
