Biết trước tên khoá → FormGroup. Chỉ biết "một danh sách" → FormArray.

2. Tách việc dựng form ra khỏi component

TypeScript · src/app/features/instructor/course-builder.service.ts 
@Injectable({ providedIn: 'root' })
export class CourseBuilderService {
  private readonly fb = inject(FormBuilder);

  // Factory: mỗi lần gọi trả về một FormGroup MỚI, độc lập.
  // Dùng chung một instance cho nhiều dòng = mọi dòng đổi cùng lúc.
  taoLesson(title = '', durationSeconds = 0): FormGroup {
    return this.fb.group({
      title: [title, [Validators.required, Validators.minLength(3)]],
      durationSeconds: [durationSeconds, [Validators.required, Validators.min(1)]],
      isFreePreview: [false],
    });
  }

  // Helper ép kiểu — dùng ở CẢ template lẫn code, viết một lần ở đây.
  lessons(section: FormGroup): FormArray {
    return section.get('lessons') as FormArray;
  }
}
🔎 Vì sao tách ra service

Component lo hiển thị; service lo cấu trúc. Nhờ vậy test logic form không cần dựng component nào — toàn bộ test Bài 19–20 của tôi chạy thẳng trên service, nhanh hơn nhiều và không phụ thuộc DOM.

3. Thêm / xoá / sắp xếp

TypeScript · API của FormArray 
const lessons = svc.lessons(section);

lessons.push(svc.taoLesson());          // thêm cuối
lessons.insert(1, svc.taoLesson());      // chèn giữa
lessons.removeAt(2);                     // xoá theo CHỈ SỐ
lessons.at(0).patchValue({ title: 'X' });
lessons.length;                            // KHÔNG phải .controls.length
lessons.clear();                          // xoá sạch
HTML · template 
<div formArrayName="lessons">
  @for (ctrl of lessons.controls; track ctrl; let i = $index) {
    <!-- formGroupName nhận CHỈ SỐ, không phải tên -->
    <div [formGroupName]="i">
      <input formControlName="title" />
      <button type="button" (click)="lessons.removeAt(i)">Xoá</button>
    </div>
  }
</div>
🔥 track $index là bẫy khi xoá giữa chừng

Có 5 lesson, xoá cái thứ 2. Với track $index, Angular thấy "index 1 giờ có nội dung khác" và tái sử dụng DOM cũ cho control mới — ô input giữ nguyên giá trị đang gõ dở của dòng cũ, và focus nhảy lung tung.

track ctrl (tham chiếu của chính control) thì Angular biết chính xác dòng nào biến mất. Đây là lý do trong @for nên track theo danh tính chứ không theo vị trí.

4. Happy path chưa đủ

⚖️ Xoá xong thì chỉ số của các control sau ĐỔI

Nếu bạn lưu selectedIndex = 3 ở đâu đó rồi xoá dòng 1, biến đó giờ trỏ nhầm dòng. Đừng giữ chỉ số làm state — hãy giữ tham chiếu control, hoặc một id trong chính giá trị form.

TypeScript · test đã verify 
it('xoá section GIỮA chừng không làm lệch các section còn lại', () => {
  sections.at(0).patchValue({ sectionTitle: 'A' });
  sections.push(svc.taoSection('B'));
  sections.push(svc.taoSection('C'));

  sections.removeAt(1);   // xoá B

  expect(sections.controls.map((c) => c.value.sectionTitle)).toEqual(['A', 'C']);
});
🎤 Góc phỏng vấn

Hỏi: "FormArray khác FormGroup ở đâu?"

Trả lời gọn: "FormGroup có tập khoá cố định, truy cập theo tên — hợp với object shape biết trước. FormArray truy cập theo chỉ số và push/removeAt lúc chạy — hợp với danh sách người dùng tự thêm bớt. Bẫy thực tế là track theo index trong @for: xoá giữa chừng sẽ khiến Angular tái dùng DOM sai dòng."

✅ Senior takeaway
  • Tôi chọn FormArray khi số lượng đổi lúc chạy, FormGroup khi shape biết trước.
