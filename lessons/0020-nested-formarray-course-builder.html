Form phức tạp nhất của app: Course → Section → Lesson, hai tầng lồng nhau.

⏱ ~50 phút · 🎯 Submit ra JSON lồng khớp types.ts · 🏷️ EduCommerce · Instructor

  • Giải thích trạng thái valid lan từ lá lên gốc thế nào.

🌉 Bắc cầu từ cái bạn đã biết

Bài 19: FormArray một tầng, factory function, track theo danh tính.

Bài này chỉ thêm một mảnh: phần tử của FormArray là FormGroup chứa FormArray khác. Không có API mới — chỉ là lồng.

1. Cấu trúc đích

Cây form 
FormGroup (course)
├─ FormControl  title
├─ FormControl  tags          ← app-tag-input (Bài 18)
└─ FormArray    sections
   └─ FormGroup [0]
      ├─ FormControl  sectionTitle
      └─ FormArray    lessons
         └─ FormGroup [0]
            ├─ FormControl  title
            ├─ FormControl  durationSeconds
            └─ FormControl  isFreePreview
TypeScript · dựng bằng factory lồng factory 
taoSection(sectionTitle = ''): FormGroup {
  return this.fb.group({
    sectionTitle: [sectionTitle, Validators.required],
    // Section mới luôn có sẵn 1 lesson — form trống hoàn toàn khiến
    // người dùng không biết phải bấm gì tiếp theo.
    lessons: this.fb.array([this.taoLesson()]),
  });
}

taoCourseForm(): FormGroup {
  return this.fb.group({
    title: ['', [Validators.required, Validators.minLength(5)]],
    tags: [[] as string[]],
    sections: this.fb.array([this.taoSection()]),
  });
}

2. Template — trả lời câu hỏi tư duy Bài 19

Angular biết formControlName="title" nói về ai nhờ ngữ cảnh lồng nhau của các directive. Mỗi tầng thu hẹp phạm vi một bậc:

HTML · course-builder.component.html 
<form [formGroup]="form">
  <input formControlName="title" />              <!-- title của COURSE -->
  <app-tag-input formControlName="tags"></app-tag-input>

  <div formArrayName="sections">
    @for (s of sections.controls; track s; let i = $index) {

      <div [formGroupName]="i">                  <!-- vào section thứ i -->
        <input formControlName="sectionTitle" />

        <div formArrayName="lessons">
          @for (l of lessonsCua(i).controls; track l; let j = $index) {

            <div [formGroupName]="j">            <!-- vào lesson thứ j -->
              <input formControlName="title" />  <!-- title của LESSON -->
              <input type="number" formControlName="durationSeconds" />
              <button type="button" (click)="xoaLesson(i, j)">Xoá bài</button>
            </div>
          }
        </div>

        <button type="button" (click)="themLesson(i)">+ Bài học</button>
        <button type="button" (click)="xoaSection(i)">Xoá chương</button>
      </div>
    }
  </div>

  <button type="button" (click)="themSection()">+ Chương</button>
  <button type="submit" [disabled]="form.invalid">Lưu</button>
</form>
💡 Hãy giữ câu này trong đầu

Mỗi formGroupName/formArrayName đi xuống một tầng của cây. formControlName luôn tương đối với tầng gần nhất bao quanh nó.

🔥 Ba lỗi template hay gặp
  • formGroupName="i" thiếu ngoặc vuông → Angular tìm khoá tên "i" chứ không phải chỉ số. Phải là [formGroupName]="i".
  • Quên <div formArrayName="lessons"> bọc ngoài → [formGroupName]="j" tìm trong section thay vì trong lessons.
  • Gọi hàm trong @for (lessonsCua(i)) chạy lại mỗi chu kỳ CD. Chấp nhận được vì nó chỉ ép kiểu; nhưng đừng đặt tính toán nặng ở đó.

3. Trạng thái lan từ lá lên gốc

TypeScript · test đã verify 
it('form INVALID khi lesson lồng sâu bị thiếu -> lỗi nổi lên tận gốc', () => {
  expect(form.valid).toBe(false);

  form.patchValue({ title: 'Angular căn bản' });
  const s0 = svc.sections(form).at(0) as FormGroup;
  s0.patchValue({ sectionTitle: 'Mở đầu' });
  svc.lessons(s0).at(0).patchValue({ title: 'Giới thiệu', durationSeconds: 60 });

  expect(form.valid).toBe(true);   // mọi lá hợp lệ -> gốc hợp lệ
});
⚖️ Ưu điểm và nhược điểm của việc lỗi nổi lên

Ưu: [disabled]="form.invalid" ở nút Lưu tự động đúng, không cần kiểm từng nhánh.

Nhược: người dùng thấy nút Lưu bị khoá mà không biết lỗi nằm ở chương 3, bài 7. Với form sâu, phải có cách chỉ đường — đánh dấu chương nào đang lỗi, hoặc cuộn tới ô sai đầu tiên khi bấm Lưu.

4. Thao tác nhánh này không đụng nhánh kia

TypeScript · test đã verify 
it('thêm lesson vào section 2 không đụng section 1', () => {
  sections.push(svc.taoSection('S2'));

  const lessons2 = svc.lessons(sections.at(1) as FormGroup);
  lessons2.push(svc.taoLesson('Bài 2', 120));

  expect(svc.lessons(sections.at(0) as FormGroup).length).toBe(1);
  expect(lessons2.length).toBe(2);
});

Test này nhìn có vẻ hiển nhiên — nhưng nó chính là thứ đỏ nếu bạn dùng lessonTemplate dùng chung thay vì factory (Bài 19, Câu 2). Nó bảo vệ bạn khỏi đúng cái bug khó tả nhất của form lồng.

5. Xuất ra JSON

TypeScript 
onSubmit(): void {
  if (this.form.invalid) {
    // Không có dòng này thì ô chưa chạm vẫn untouched -> không hiện lỗi,
    // người dùng bấm Lưu và "không có gì xảy ra".
    this.form.markAllAsTouched();
    return;
  }
  // getRawValue() để lấy cả control disabled (Bài 15).
  this.courseService.create(this.form.getRawValue()).subscribe();
}

🎤 Góc phỏng vấn

Hỏi: "Làm form lồng nhiều tầng thế nào, khó nhất ở đâu?"

Trả lời gọn: "FormArray chứa FormGroup chứa FormArray, dựng bằng factory function để mỗi nhánh có state độc lập. Template lồng formArrayName → [formGroupName]="i" theo đúng tầng. Khó nhất không phải cú pháp mà là UX: lỗi ở lá làm cả form invalid, nên phải chỉ đường cho người dùng biết lỗi nằm ở chương nào bài nào, chứ không chỉ khoá nút Lưu."

🧠 Kiểm tra mental model

Câu 1. Bạn viết <div formGroupName="i"> (không có ngoặc vuông). Chuyện gì xảy ra?
Câu 2. Form có 5 chương, 40 bài. Người dùng bấm Lưu, nút bị khoá vì form.invalid. Vấn đề UX ở đây là gì?

🧩 Hint ladder

Hint 1: Dựng và test service cho xong trước, template làm sau. Sai cấu trúc mà đi sửa template là gấp đôi công.
