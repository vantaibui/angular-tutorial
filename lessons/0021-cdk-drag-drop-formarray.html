CDK Drag & Drop — sắp xếp trong FormArray

Đổi vị trí control mà không dựng lại nó — nên không mất trạng thái.

⏱ ~35 phút · 🎯 Kéo thả chương/bài, giữ nguyên data · 🏷️ EduCommerce · Instructor

🎯 Sau bài này bạn phải làm được
  • Cắm CDK Drag & Drop vào một FormArray.
  • Đổi vị trí bằng removeAt + insert và nói được vì sao không dựng lại control.
  • Đồng bộ thứ tự DOM với thứ tự dữ liệu — hai thứ khác nhau.
  • Test logic sắp xếp mà không cần mô phỏng chuột.

3. Code

HTML 
<div formArrayName="sections" cdkDropList (cdkDropListDropped)="doiChoSection($event)">
  @for (s of sections.controls; track s; let i = $index) {
    <div [formGroupName]="i" cdkDrag>
      <!-- Handle riêng: kéo bằng icon, không kéo bằng cả khối -->
      <!-- Thiếu handle thì chọn chữ trong input cũng kích hoạt kéo -->
      <span cdkDragHandle class="handle">⠿</span>
      <input formControlName="sectionTitle" />
    </div>
  }
</div>
TypeScript 
import { CdkDragDrop } from '@angular/cdk/drag-drop';

doiChoSection(ev: CdkDragDrop<unknown[]>): void {
  if (ev.previousIndex === ev.currentIndex) return;   // thả tại chỗ

  const arr = this.sections;

  // GIỮ NGUYÊN control rồi chèn lại — KHÔNG tạo control mới.
  // Tạo mới sẽ mất touched/dirty/errors và cả những gì đang gõ dở.
  const ctrl = arr.at(ev.previousIndex);
  arr.removeAt(ev.previousIndex);
  arr.insert(ev.currentIndex, ctrl);

  // Sắp xếp là một thay đổi thật -> đánh dấu để nút Lưu bật lên.
  arr.markAsDirty();
}
🔥 Đừng dùng patchValue để sắp xếp
TypeScript · ❌ cách sai hay gặp 
const giaTri = arr.getRawValue();
moveItemInArray(giaTri, ev.previousIndex, ev.currentIndex);
arr.patchValue(giaTri);   // ← giá trị đổi, nhưng CONTROL thì không

Cách này chỉ chép giá trị sang control ở vị trí khác. Hậu quả:

  • Trạng thái touched/dirty ở lại sai dòng.
  • Thông báo lỗi hiện ở dòng không có lỗi.
  • Với form lồng (Bài 20), mảng lessons bên trong bị chép cạn — hai section dùng chung tham chiếu.

Di chuyển control, không phải chép giá trị.

4. Test không cần chuột

Mô phỏng thao tác kéo trong test rất phiền và giòn. Nhưng thứ đáng test không phải cử chỉ chuột — mà là logic sắp xếp. Gọi thẳng handler:

TypeScript · test đã verify 
it('đổi chỗ 2 section giữ nguyên toàn bộ data con', () => {
  sections.at(0).patchValue({ sectionTitle: 'A' });
  sections.push(svc.taoSection('B'));

  // Chính kỹ thuật CDK dùng — test được mà không cần chuột.
  const ctrl = sections.at(0);
  sections.removeAt(0);
  sections.insert(1, ctrl);

  expect(sections.controls.map((c) => c.value.sectionTitle)).toEqual(['B', 'A']);
});
🎤 Góc phỏng vấn

Hỏi: "Kéo thả để sắp xếp FormArray — cần lưu ý gì?"

Trả lời gọn: "CDK chỉ đổi DOM và báo cặp index; mình phải tự đổi trong FormArray, nếu không dữ liệu submit vẫn thứ tự cũ. Quan trọng là di chuyển control bằng removeAt+insert, chứ không patchValue giá trị — chép giá trị làm touched/dirty và lỗi ở lại sai dòng. Và luôn dùng cdkDragHandle, nếu không người dùng không bôi đen được chữ trong input."

6. Câu hỏi tư duy

Bạn vừa hard-code template cho Course info: title, tags, level… Sắp tới cần form sửa Category, form profile User, form Coupon — mỗi cái một template riêng, nhưng cấu trúc thì giống hệt: nhãn, ô nhập, thông báo lỗi.

Nếu bạn mô tả form bằng một mảng object (field nào, kiểu gì, validator gì) thì một component duy nhất render được mọi form.

Nhưng làm sao để gõ sai tên field là lỗi biên dịch, chứ không phải bug runtime? Bài 14 đã cho bạn thấy route.data gõ nhầm nguy hiểm thế nào.
