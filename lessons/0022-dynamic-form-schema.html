1. Bài toán thật: cùng một khuôn, chép năm lần

Form Course, Category, User profile, Coupon — cấu trúc HTML giống hệt: nhãn, ô nhập, thông báo lỗi. Chỉ khác danh sách field.

Chép template năm lần nghĩa là: đổi cách hiển thị lỗi phải sửa năm chỗ, và chắc chắn sẽ có một chỗ bị bỏ sót.

🤔 Trước khi nhìn lời giải

Thứ thay đổi giữa năm form là dữ liệu (danh sách field), không phải logic (dựng control, render, hiện lỗi). Đúng bài toán Bài 14 đã giải cho guard bằng route.data — chỉ khác quy mô.

2. Schema — và keyof để không gõ sai tên

TypeScript · src/app/shared/dynamic-form/form-field-schema.ts 
export type FieldType = 'text' | 'number' | 'textarea' | 'select' | 'rating' | 'tags';

/**
 * K ràng buộc theo keyof TModel -> gõ sai tên field là LỖI BIÊN DỊCH,
 * không phải bug runtime (đúng bài học Bài 05 mục 5).
 */
export interface FormFieldSchema<
  TModel = Record<string, unknown>,
  K extends keyof TModel = keyof TModel,
> {
  name: K;
  label: string;
  type: FieldType;
  // TModel[K]: giá trị mặc định phải ĐÚNG KIỂU của chính field đó.
  defaultValue?: TModel[K];
  validators?: ValidatorFn[];
  options?: { value: string; label: string }[];   // cho 'select'
  maxTags?: number;                                // cho 'tags'
}
TypeScript · dùng có kiểu 
const courseSchema: FormFieldSchema<Course>[] = [
  { name: 'title', label: 'Tiêu đề', type: 'text', validators: [Validators.required] },
  { name: 'price', label: 'Giá', type: 'number' },
  { name: 'tags', label: 'Thẻ', type: 'tags', maxTags: 5 },
];

// @ts-expect-error 'titel' không phải field của Course
const sai: FormFieldSchema<Course>[] = [{ name: 'titel', label: 'X', type: 'text' }];
🔎 Vì sao keyof đáng công ở đây

Bài 14 bạn thấy route.data gõ nhầm role/roles biến route admin thành công khai — không lỗi biên dịch nào. Schema form cũng là dữ liệu thô, và cũng dễ gõ nhầm y hệt.

Khác biệt: ở đây ta ràng buộc được. K extends keyof TModel biến lỗi chính tả từ bug runtime thành lỗi đỏ trong IDE. Đó là lý do Bài 05 nằm ở Module 1.

3. Component

TypeScript · dựng FormGroup từ schema 
export class DynamicFormComponent implements OnInit {
  @Input({ required: true }) schema: FormFieldSchema[] = [];
  @Input() initialValue: Record<string, unknown> = {};
  @Output() submit = new EventEmitter<Record<string, unknown>>();

  private readonly fb = inject(FormBuilder);
  form!: FormGroup;

  // ngOnInit chứ không phải constructor: @Input chưa có giá trị lúc constructor chạy.
  ngOnInit(): void { this.form = this.buildForm(); }

  private buildForm(): FormGroup {
    const controls: Record<string, unknown[]> = {};
    for (const f of this.schema) {
      const key = f.name as string;
      // Thứ tự ưu tiên: giá trị truyền vào > mặc định của schema > mặc định theo type
      const giaTri = this.initialValue[key] ?? f.defaultValue ?? this.macDinhTheoType(f.type);
      controls[key] = [giaTri, f.validators ?? []];
    }
    return this.fb.group(controls);
  }

  // Mặc định SAI KIỂU là nguồn bug: tags phải là [], không phải ''.
  private macDinhTheoType(type: string): unknown {
    if (type === 'tags') return [];
    if (type === 'rating' || type === 'number') return 0;
    return '';
  }
}
HTML · @switch chọn control theo type 
<form [formGroup]="form" (ngSubmit)="submit.emit(form.getRawValue())">
  @for (field of schema; track field.name) {
    <div class="field">
      <label [attr.for]="field.name">{{ field.label }}</label>

      @switch (field.type) {
        @case ('textarea') { <textarea [formControlName]="field.name"></textarea> }
        @case ('select') {
          <select [formControlName]="field.name">
            @for (opt of field.options ?? []; track opt.value) {
              <option [value]="opt.value">{{ opt.label }}</option>
            }
          </select>
        }
        <!-- Custom control Bài 17-18 cắm vào y như control chuẩn -->
        @case ('rating') { <app-rating-input [formControlName]="field.name"></app-rating-input> }
        @case ('tags')   { <app-tag-input [formControlName]="field.name" [maxTags]="field.maxTags ?? 5"></app-tag-input> }
        @default         { <input [type]="field.type" [formControlName]="field.name" /> }
      }

      @if (form.get(field.name)?.invalid && form.get(field.name)?.touched) {
        <small class="err">{{ field.label }} không hợp lệ</small>
      }
    </div>
  }
  <button type="submit" [disabled]="form.invalid">Lưu</button>
</form>
🔎 Đây là lúc công sức Bài 17–18 được trả lại

<app-rating-input> cắm vào đây không cần sửa gì, vì nó đã tuân thủ hợp đồng ControlValueAccessor. Nếu nó chỉ là component với @Output thì bạn sẽ phải viết code đặc biệt cho riêng nó trong dynamic form — và ý tưởng "một component render mọi form" sụp đổ.

4. Chứng minh nó thật sự tái sử dụng

TypeScript · test đã verify 
it('ĐỔI SCHEMA -> form đổi theo, KHÔNG sửa template', () => {
  const f2 = TestBed.createComponent(DynamicFormComponent);
  f2.componentInstance.schema = [
    { name: 'price', label: 'Giá', type: 'number' },
    { name: 'desc', label: 'Mô tả', type: 'textarea' },
  ];
  f2.detectChanges();

  expect(Object.keys(f2.componentInstance.form.controls)).toEqual(['price', 'desc']);
  expect(f2.nativeElement.querySelector('textarea')).toBeTruthy();
});

5. Khi nào KHÔNG nên dùng dynamic form

🎤 Góc phỏng vấn

Hỏi: "Bạn từng làm dynamic form chưa? Đánh đổi là gì?"

Trả lời gọn: "Có — schema mô tả field, một component dựng FormGroup qua vòng lặp và @switch theo type, custom control cắm vào được nhờ ControlValueAccessor. Đánh đổi: mất layout tự do, logic liên field phải nhét vào schema, và thông báo lỗi trở nên chung chung. Tôi dùng nó cho các form CRUD admin giống nhau, còn form đăng ký hay checkout thì viết tay — ở đó UX quan trọng hơn tái sử dụng."
