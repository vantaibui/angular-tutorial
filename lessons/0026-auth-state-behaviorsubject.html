Auth state bằng BehaviorSubject

private Subject + public asObservable() — pattern một-chiều-ghi từ Bài 03, lần này cho chính AuthService.

⏱ ~35 phút · 🎯 Header/Guard/Profile đọc cùng một nguồn sự thật · 🏷️ EduCommerce · Auth

🎯 Sau bài này bạn phải làm được
  • Thiết kế AuthService phục vụ cả đọc snapshot lẫn subscribe liên tục.
  • Đảm bảo không ai bên ngoài tự ý ghi đè trạng thái đăng nhập.
  • Dẫn xuất isAuthenticated$ từ currentUser$ mà không giữ state riêng.
  • Không leak subscription khi dùng | async lẫn subscribe() thủ công.
🌉 Bắc cầu từ cái bạn đã biết

Bài 03 bạn tự trả lời: giỏ hàng là trạng thái nên dùng BehaviorSubject, và private Subject + public asObservable() đóng cửa ghi ở tầng kiểu. Bài 25 vừa cho thấy AuthInterceptor cần đọc/ghi token — nhưng AuthService hiện tại quá sơ sài.

Bài này chỉ thêm một mảnh mới: áp đúng pattern đó cho auth, và phục vụ hai kiểu tiêu thụ khác nhau — đọc một lần và theo dõi liên tục.

🤔 Trước khi nhìn lời giải

Guard và Interceptor không thể await một Observable giữa chừng vòng đời của chúng — chúng cần câu trả lời ngay. Header thì ngược lại, cần biết mọi lần thay đổi trong tương lai. Một cấu trúc dữ liệu nào cho cả hai?

2. Mental model: một nguồn, hai cách lấy ra

BehaviorSubject cho cả hai kiểu đọc — đúng vì nó LUÔN có giá trị hiện tại (Bài 03) 
private readonly currentUserSubject = new BehaviorSubject<User | null>(null);

// Kiểu 1: SUBSCRIBE LIÊN TỤC — cho Header, template dùng | async
readonly currentUser$ = this.currentUserSubject.asObservable();

// Kiểu 2: ĐỌC SNAPSHOT ĐỒNG BỘ — cho Guard, Interceptor
get currentUser(): User | null { return this.currentUserSubject.value; }
💡 Hãy giữ câu này trong đầu

Một BehaviorSubject phục vụ được cả hai kiểu đọc, vì .value và .asObservable() chỉ là hai CỬA SỔ khác nhau nhìn vào CÙNG một trạng thái.

Không cần hai biến riêng để đồng bộ thủ công — chỉ cần một nguồn sự thật.

3. Code đầy đủ

TypeScript · src/app/core/services/auth.service.ts 
@Injectable({ providedIn: 'root' })
export class AuthService {
  private readonly http = inject(HttpClient);

  // private: CHỈ AuthService được quyền next(). Không ai bên ngoài ghi đè trạng thái.
  private readonly currentUserSubject = new BehaviorSubject<User | null>(null);
  readonly currentUser$ = this.currentUserSubject.asObservable();

  // Dẫn xuất — KHÔNG giữ state riêng, luôn tự động đồng bộ với currentUser$.
  readonly isAuthenticated$ = this.currentUser$.pipe(map((u) => u !== null));

  login(email: string, password: string): Observable<LoginResponse> {
    return this.http.post<LoginResponse>('/api/auth/login', { email, password }).pipe(
      tap((res) => {
        localStorage.setItem(ACCESS_TOKEN_KEY, res.accessToken);
        localStorage.setItem(REFRESH_TOKEN_KEY, res.refreshToken);
        this.currentUserSubject.next(res.user);  // MỘT nơi duy nhất gọi next()
      }),
    );
  }

  logout(): void {
    localStorage.removeItem(ACCESS_TOKEN_KEY);
    localStorage.removeItem(REFRESH_TOKEN_KEY);
    this.currentUserSubject.next(null);
  }

  get accessToken(): string | null { return localStorage.getItem(ACCESS_TOKEN_KEY); }
  get isLoggedIn(): boolean { return this.currentUserSubject.value !== null; }
  get currentUser(): User | null { return this.currentUserSubject.value; }
}
🔎 Vì sao isAuthenticated$ không phải một BehaviorSubject khác

Nếu bạn tạo isAuthenticatedSubject riêng, bạn phải nhớ gọi .next() ở cả hai chỗ — login() và logout() — và chúng có thể lệch nhau nếu quên một chỗ. Dẫn xuất bằng .pipe(map(...)) nghĩa là chỉ có một nguồn sự thật (currentUserSubject); mọi luồng khác tự động đúng theo nó, không thể lệch.

4. Component subscribe đúng cách

HTML · header.component.html 
<!-- | async: Angular tự subscribe/unsubscribe theo vòng đời component (Bài 03) -->
@if (auth.currentUser$ | async; as user) {
  <span>Xin chào, {{ user.name }}</span>
  <button (click)="auth.logout()">Đăng xuất</button>
} @else {
  <a routerLink="/login">Đăng nhập</a>
}
🔥 Nếu bạn subscribe() thủ công thay vì | async

Đúng bài học Bài 02: this.auth.currentUser$.subscribe(...) trong ngOnInit mà quên takeUntil(this.destroy$) thì mỗi lần component header bị tạo lại (hiếm, nhưng có thể xảy ra khi route thay đổi layout) sẽ để lại một subscription sống mãi, giữ tham chiếu tới component cũ. | async tránh được toàn bộ vấn đề này — đây là lý do nó là lựa chọn mặc định.

5. Test — chứng minh cả hai kiểu đọc đều đúng

TypeScript · test đã verify xanh 
it('login thành công: lưu token, currentUser$ phát user mới', async () => {
  const emitted: (User | null)[] = [];
  const sub = service.currentUser$.subscribe((u) => emitted.push(u));

  const p = firstValueFrom(service.login('t@x.vn', '123'));
  httpMock.expectOne('/api/auth/login').flush({
    user: fakeUser, accessToken: 'acc-1', refreshToken: 'ref-1',
  });
  await p;

  expect(emitted).toEqual([null, fakeUser]);  // null lúc đầu (BehaviorSubject), rồi user sau login
  expect(service.isLoggedIn).toBe(true);
  sub.unsubscribe();
});

it('người subscribe MUỘN vẫn nhận đúng trạng thái hiện tại', async () => {
  const p = firstValueFrom(service.login('t@x.vn', '123'));
  httpMock.expectOne('/api/auth/login').flush({ user: fakeUser, accessToken: 'acc-1', refreshToken: 'ref-1' });
  await p;

  // Subscribe SAU khi login xong -> vẫn thấy user NGAY, đúng tính chất BehaviorSubject (Bài 03)
  const late = await firstValueFrom(service.currentUser$.pipe(take(1)));
  expect(late).toEqual(fakeUser);
});
🎤 Góc phỏng vấn

Hỏi: "Thiết kế state service cho auth thế nào để an toàn?"

Trả lời gọn: "Một BehaviorSubject private giữ trạng thái, expose asObservable() công khai để chặn ghi từ ngoài ở tầng kiểu. Mọi luồng dẫn xuất (isAuthenticated$) dùng pipe(map(...)) thay vì subject riêng, để không có hai nguồn sự thật lệch nhau. Nơi cần đọc đồng bộ (guard, interceptor) dùng getter đọc .value; nơi cần theo dõi liên tục (template) dùng | async trên chính Observable đó — cùng một nguồn, hai cách lấy."

🧠 Kiểm tra mental model

Câu 1. Vì sao isAuthenticated$ nên là currentUser$.pipe(map(...)) thay vì một BehaviorSubject<boolean> riêng?

✅ Senior takeaway
  • Tôi thiết kế được một service phục vụ cả đọc snapshot lẫn subscribe liên tục từ CÙNG một nguồn.
  • Tôi dẫn xuất luồng phụ bằng map, không tạo Subject riêng dễ lệch.
  • Tôi biết khi nào dùng getter đồng bộ (Guard/Interceptor) và khi nào dùng | async (template).
  • Tôi đóng cửa ghi bằng asObservable(), không chỉ bằng quy ước "đừng gọi next() từ ngoài".

7. Câu hỏi tư duy

AuthService giờ đã đầy đủ. Nhưng có một tình huống chưa xử lý: người dùng quên mật khẩu. Họ chưa đăng nhập được — không có access token, không có currentUser — nên toàn bộ luồng bạn vừa xây không áp dụng được ở đây.

Thay vào đó, họ nhận một email chứa link kiểu /reset-password?token=xyz. Component đọc token đó từ đâu — nó không nằm trong path, không phải path param như /:id bạn đã quen ở Bài 12–14?
