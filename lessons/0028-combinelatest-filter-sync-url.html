Phase 5 · Bài 28 · Course Listing

combineLatest gộp filter + sync URL

3 ô filter độc lập (search, category, page), 1 pipeline fetch duy nhất — và URL phải nhớ được filter để refresh trang hay gửi link cho đồng nghiệp không bị mất trạng thái.

⏱ ~40 phút · 🎯 Mở Module 6 — pipeline RxJS Bài 01 cắm vào app thật

🎯 Sau bài này bạn phải làm được
  • Giải thích vì sao combineLatest cần dùng BehaviorSubject chứ không phải Subject trơn cho từng filter.
  • Đọc filter TỪ URL đúng một lần lúc vào trang (snapshot), và ghi filter LÊN URL mỗi khi nó đổi.
  • Giải thích vì sao replaceUrl: true quan trọng ở đây — filter không phải điều hướng, không nên phá lịch sử back/forward.
🌉 Bắc cầu từ cái bạn đã biết

Bài 01: combineLatest im lặng cho tới khi MỌI nguồn phát ít nhất một giá trị. Bài 03: BehaviorSubject luôn có "giá trị hiện tại" ngay khi subscribe. Bài 27: đọc query param qua snapshot khi chỉ cần đọc một lần lúc khởi tạo.

Bài này ghép cả ba lại: dùng BehaviorSubject cho từng filter (đảm bảo combineLatest phát ngay từ đầu), và snapshot để khôi phục filter từ URL.

1. Bài toán thật: 3 ô filter, 1 danh sách

Trang danh sách khoá học có ô tìm kiếm, dropdown danh mục, và phân trang. Mỗi ô đổi phải gọi lại GET /api/courses với tham số tương ứng — nhưng nếu người dùng gõ tìm kiếm RỒI đổi danh mục, bạn không muốn viết 3 khối code gọi API gần giống hệt nhau, mỗi khối lo một tổ hợp filter.

Thêm một yêu cầu thật: người dùng lọc xong, bấm F5 hoặc gửi link cho đồng nghiệp — filter phải còn nguyên. Nghĩa là trạng thái filter không chỉ sống trong component, nó phải phản ánh ra URL.

🤔 Trước khi nhìn lời giải

Bạn có 3 nguồn giá trị độc lập (search, category, page) nhưng chỉ cần MỘT hành động cuối cùng mỗi khi bất kỳ nguồn nào đổi: gọi lại API với tổ hợp mới nhất của cả ba. Toán tử nào trong RxJS sinh ra đúng cho việc "gộp N nguồn, phát lại mỗi khi MỘT trong số chúng đổi"?

2. Mental model: combineLatest cần MỌI nguồn có giá trị

Nhắc lại Bài 01 — bẫy im lặng 
const searchSubject = new Subject<string>();     // ❌ Subject trơn: chưa .next() lần nào thì chưa có gì
const categorySubject = new Subject<string>();

combineLatest([searchSubject, categorySubject]).subscribe(...);
// Nếu người dùng chỉ gõ search mà CHƯA đụng vào category -> combineLatest KHÔNG BAO GIỜ phát,
// vì categorySubject chưa có giá trị nào. Y hệt bẫy "combineLatest im lặng" ở Bài 01.
✅ Lời giải: BehaviorSubject — luôn có giá trị khởi tạo 
const searchSubject = new BehaviorSubject<string>('');     // có giá trị NGAY từ khi tạo
const categorySubject = new BehaviorSubject<string>('');
const pageSubject = new BehaviorSubject<number>(1);

combineLatest([searchSubject, categorySubject, pageSubject]).subscribe(...);
// Phát NGAY một lần lúc subscribe (['', '', 1]), rồi phát lại mỗi khi BẤT KỲ nguồn nào .next().

Đây chính là lý do Bài 03 nhấn BehaviorSubject "luôn có giá trị hiện tại" — tính chất đó không chỉ hữu ích cho auth state, nó là điều kiện bắt buộc để combineLatest hoạt động đúng ngay từ khung hình đầu tiên.

3. Code đầy đủ

TypeScript · src/app/features/courses/course-list/course-list.component.ts 
const PAGE_SIZE = 12;

@Component({
  selector: 'app-course-list',
  standalone: false,
  templateUrl: './course-list.component.html',
})
export class CourseListComponent implements OnInit, OnDestroy {
  private readonly destroy$ = new Subject<void>();
  private readonly searchSubject = new BehaviorSubject<string>('');
  private readonly categorySubject = new BehaviorSubject<string>('');
  private readonly pageSubject = new BehaviorSubject<number>(1);

  result: ApiListResponse<Course> | null = null;

  constructor(
    private readonly courseService: CourseService,
    private readonly route: ActivatedRoute,
    private readonly router: Router,
  ) {}

  ngOnInit(): void {
    // Đọc URL 1 LẦN lúc vào trang — snapshot, không subscribe liên tục (Bài 27).
    // Đủ dùng vì chính component này là nơi DUY NHẤT ghi url trong lúc nó còn sống.
    const qp = this.route.snapshot.queryParamMap;
    this.searchSubject.next(qp.get('search') ?? '');
    this.categorySubject.next(qp.get('category') ?? '');
    this.pageSubject.next(Number(qp.get('page') ?? 1));

    combineLatest([this.searchSubject, this.categorySubject, this.pageSubject])
      .pipe(
        tap(([search, category, page]) => this.syncUrl(search, category, page)),
        switchMap(([search, category, page]) =>
          this.courseService.getAll({
            ...(search ? { search } : {}),
            ...(category ? { category } : {}),
            page,
            limit: PAGE_SIZE,
          }),
        ),
        takeUntil(this.destroy$),
      )
      .subscribe((res) => (this.result = res));
  }

  ngOnDestroy(): void {
    this.destroy$.next();
    this.destroy$.complete();
  }

  onSearch(value: string): void { this.searchSubject.next(value); }
  onCategory(value: string): void { this.categorySubject.next(value); }
  onPage(page: number): void { this.pageSubject.next(page); }

  private syncUrl(search: string, category: string, page: number): void {
    this.router.navigate([], {
      relativeTo: this.route,
      queryParams: { search: search || null, category: category || null, page },
      queryParamsHandling: 'merge',
      replaceUrl: true,   // filter KHÔNG phải điều hướng — đừng phá lịch sử back/forward
    });
  }
}
🔎 Vì sao router.navigate([]) (mảng rỗng) mà không phải navigate(['/courses'])

Mảng rỗng + relativeTo: this.route nghĩa là "ở nguyên route hiện tại, chỉ đổi query params". Bạn không muốn gõ cứng path — nếu route này bị đổi tên hay lồng sâu hơn, code này vẫn đúng vì nó không biết (và không cần biết) path tuyệt đối là gì.

🔥 search: search || null chứ không phải search: search

Angular Router xoá query param khỏi URL khi giá trị là null hoặc undefined, nhưng vẫn giữ nó (dạng ?search=) khi giá trị là chuỗi rỗng ''. Xoá search text thì bạn muốn URL sạch (/courses?page=1), không phải /courses?search=&page=1.

7. Câu hỏi tư duy

Bug ở mục 5 rất lạ: this.result = res chạy đúng (bạn đọc được state mới), nhưng template không vẽ lại — dù component này không dùng ChangeDetectionStrategy.OnPush.

Bài 16 mục 5 đã dạy: zoneless cần markForCheck() khi state đổi ngoài một event template (ở đó là writeValue của CVA). Ở đây, việc "đổi state" xảy ra trong callback .subscribe() của một Observable — cũng là một sự kiện ngoài event template.

Có cách nào để Angular tự lo việc "báo view vẽ lại" mỗi khi Observable phát giá trị mới, mà bạn không cần gọi markForCheck() thủ công ở mọi nơi có .subscribe()?
