Phase 5 · Bài 29 · Course Listing

async pipe & pagination không bắn API thừa

DOM không tự cập nhật ở Bài 28 không phải lỗi vặt — nó là dấu hiệu cho thấy combineLatest 3 nguồn rời rạc đã tới giới hạn. Sửa đúng cách giải quyết luôn 2 việc khác: debounce bàn phím và không bắn API thừa.

⏱ ~45 phút · 🎯 Kết nối Bài 02 (unsubscribe) + Bài 16 (zoneless)

🎯 Sau bài này bạn phải làm được
  • Giải thích chính xác vì sao | async khiến DOM tự cập nhật mà .subscribe() thủ công thì không, ở app zoneless.
  • Đặt debounceTime ĐÚNG vị trí — trên luồng bàn phím thô, không trên state đã gộp.
  • Giải thích vì sao 3 BehaviorSubject rời rạc gây bắn API thừa khi 2 filter cần đổi CÙNG LÚC, và 1 state object giải quyết được.
🌉 Bắc cầu từ cái bạn đã biết

Bài 02: quên .unsubscribe() là leak. Bài 16 mục 5: zoneless cần markForCheck() khi state đổi ngoài một event template. Hai bài học này thực ra chỉ là MỘT nguyên tắc nhìn từ hai góc: AsyncPipe tự làm cả hai việc đó cho bạn — tự unsubscribe khi component huỷ, và tự gọi markForCheck() mỗi khi Observable phát giá trị mới.

1. Mổ xẻ bug ở Bài 28

Test bạn viết ở Bài 28 (nếu làm theo gợi ý TC5) cho thấy: this.result = res chạy đúng trong callback .subscribe(), nhưng fixture.detectChanges() gọi lại sau đó vẫn không vẽ dữ liệu mới lên DOM.

TypeScript · test tái hiện bug (đã verify — dòng cuối THẤT BẠI trên code Bài 28) 
httpMock.expectOne((r) => r.url === '/api/courses').flush({
  data: [{ id: 'c1', title: 'Đã có dữ liệu', price: 1000 }],
  meta: { page: 1, limit: 12, total: 1, totalPages: 1 },
});

expect(fixture.componentInstance.result?.data[0].title).toBe('Đã có dữ liệu'); // ✅ state ĐÚNG
fixture.detectChanges();
expect(fixture.nativeElement.textContent).toContain('Đã có dữ liệu');          // ❌ DOM vẫn KHÔNG có chữ này

Nguyên nhân giống hệt Bài 16 mục 5, chỉ khác bối cảnh: CourseListComponent không dùng OnPush, nhưng project của bạn zoneless từ Bài 00. Zoneless không quan tâm bạn dùng Default hay OnPush — nó chỉ vẽ lại view khi có ai đó báo nó biết "có gì đổi". Một sự kiện template (click, input) tự động báo. Một callback .subscribe() chạy từ HTTP response thì không — Angular không có cách nào biết bạn vừa gán lại một field.

💡 Vậy tại sao Bài 16-27 không gặp bug này?

Những bài trước hoặc dùng | async sẵn (không tự subscribe), hoặc mutate state NGAY TRONG một handler sự kiện template ((click), (input)) — trường hợp đó Angular tự biết phải kiểm tra lại view sau khi handler chạy xong. CourseListComponent là bài ĐẦU TIÊN tự .subscribe() một Observable bắt nguồn từ HTTP, ngoài mọi sự kiện template — nên bug mới lộ ra ở đây.

2. Vì sao không chỉ vá bằng markForCheck()

Bạn có thể inject ChangeDetectorRef và gọi markForCheck() trong .subscribe() — nó sẽ hết bug. Nhưng đó là vá triệu chứng. Vấn đề sâu hơn: bạn đang tự quản lý một Observable (subscribe, giữ state, nhớ báo CD) trong khi Angular có sẵn một công cụ làm đúng ba việc đó tự động: | async.

.subscribe() thủ công| async
Tự unsubscribe khi component huỷ❌ phải tự takeUntil (Bài 02)✅ tự động
Báo CD vẽ lại (zoneless)❌ phải tự markForCheck()✅ tự động
Số dòng code trong componentNhiều hơnÍt hơn

Đổi result: ApiListResponse<Course> | null (field tự gán) thành result$: Observable<ApiListResponse<Course>> (expose thẳng ra template), rồi dùng *ngIf="result$ | async as r".

3. Vấn đề thứ hai: đổi search PHẢI reset về trang 1 — nhưng đừng bắn 2 request

Một yêu cầu UX rất tự nhiên: đổi search hoặc category thì nên nhảy về trang 1 (trang 5 của kết quả cũ gần như chắc chắn không còn ý nghĩa với kết quả mới). Thử làm với 3 BehaviorSubject rời rạc của Bài 28:

TypeScript · ❌ trông hợp lý — nhưng bắn 2 request cho 1 lần gõ 
onSearch(value: string): void {
  this.pageSubject.next(1);        // combineLatest phát lần 1 — page vừa đổi
  this.searchSubject.next(value); // combineLatest phát lần 2 — search vừa đổi
}
// 1 lần gõ -> 2 emission -> 2 lời gọi API, request đầu gần như vô nghĩa (state cũ + page mới)

combineLatest phát lại mỗi khi MỘT nguồn đổi — đó là đúng thiết kế của nó, nhưng nó không cho bạn cách gộp 2 thay đổi liên quan thành 1 emission nguyên tử. Khi các filter liên quan tới nhau (đổi cái này phải kéo theo reset cái khác), mô hình đúng không phải "N nguồn rời rạc + combineLatest" mà là 1 state object + patch từng phần.

TypeScript · ✅ 1 state, 1 emission mỗi lần đổi 
interface FilterState { search: string; category: string; page: number; }

private readonly filterSubject = new BehaviorSubject<FilterState>({ search: '', category: '', page: 1 });

onSearch(value: string): void {
  this.patchFilter({ search: value, page: 1 }); // MỘT .next() duy nhất, cả 2 field đổi cùng lúc
}

private patchFilter(patch: Partial<FilterState>): void {
  this.filterSubject.next({ ...this.filterSubject.value, ...patch });
}
🎤 Câu phỏng vấn ẩn trong bài này

"Khi nào dùng combineLatest nhiều nguồn, khi nào gộp thành 1 state object?" — Trả lời: combineLatest hợp cho các nguồn thực sự độc lập (không nguồn nào cần biết về nguồn khác). Khi một thay đổi PHẢI kéo theo thay đổi khác một cách nguyên tử (search đổi → page reset), gộp thành 1 state object với patch() tránh được N emission cho 1 hành động của người dùng.

4. Vấn đề thứ ba: debounce ĐÚNG chỗ

Đặt debounceTime ngay trên filterSubject (state đã gộp) trông tiện, nhưng nó áp dụng cho MỌI emission — kể cả emission ĐẦU TIÊN lúc component vừa vào trang. Hậu quả: mọi lần load trang đều bị trễ 300ms một cách vô lý, dù chưa ai gõ gì.

TypeScript · ✅ debounce trên bàn phím THÔ, không trên state đã gộp 
private readonly searchInput$ = new Subject<string>();  // raw keystroke, chưa qua state

ngOnInit(): void {
  ...
  this.searchInput$
    .pipe(debounceTime(300), distinctUntilChanged(), takeUntil(this.destroy$))
    .subscribe((search) => this.patchFilter({ search, page: 1 }));

  // KHÔNG debounce ở đây — debounce đã xảy ra Ở NGUỒN trước khi tới filterSubject.
  this.result$ = this.filterSubject.pipe(
    distinctUntilChanged(sameFilter),   // bấm lại ĐÚNG trang/category cũ -> không bắn thêm request
    tap((f) => this.syncUrl(f)),
    switchMap((f) => this.courseService.getAll({ ...f, limit: PAGE_SIZE })),
  );
}

onSearchInput(value: string): void { this.searchInput$.next(value); }   // gọi từ (input) trong template
onCategory(value: string): void { this.patchFilter({ category: value, page: 1 }); } // KHÔNG debounce — click, không phải gõ phím

Category và page là hành động click, không phải gõ liên tục — chúng không cần debounce, chỉ search text (gõ từng ký tự) mới cần. Đặt debounce đúng NGUỒN thay vì trên state tổng hợp giữ cho lần load đầu tiên nhanh như cũ.

5. Code đầy đủ

TypeScript · src/app/features/courses/course-list/course-list.component.ts (bản đủ) 
function sameFilter(a: FilterState, b: FilterState): boolean {
  return a.search === b.search && a.category === b.category && a.page === b.page;
}

@Component({ selector: 'app-course-list', standalone: false, templateUrl: './course-list.component.html' })
export class CourseListComponent implements OnInit, OnDestroy {
  private readonly destroy$ = new Subject<void>();
  private readonly searchInput$ = new Subject<string>();
  private readonly filterSubject = new BehaviorSubject<FilterState>({ search: '', category: '', page: 1 });

  result$!: Observable<ApiListResponse<Course>>;

  ngOnInit(): void {
    const qp = this.route.snapshot.queryParamMap;
    this.filterSubject.next({
      search: qp.get('search') ?? '',
      category: qp.get('category') ?? '',
      page: Number(qp.get('page') ?? 1),
    });

    this.searchInput$.pipe(debounceTime(300), distinctUntilChanged(), takeUntil(this.destroy$))
      .subscribe((search) => this.patchFilter({ search, page: 1 }));

    this.result$ = this.filterSubject.pipe(
      distinctUntilChanged(sameFilter),
      tap((f) => this.syncUrl(f)),
      switchMap((f) => this.courseService.getAll({
        ...(f.search ? { search: f.search } : {}),
        ...(f.category ? { category: f.category } : {}),
        page: f.page,
        limit: PAGE_SIZE,
      })),
      takeUntil(this.destroy$),
    );
  }

  onSearchInput(value: string): void { this.searchInput$.next(value); }
  onCategory(value: string): void { this.patchFilter({ category: value, page: 1 }); }
  onPage(page: number): void { this.patchFilter({ page }); }

  private patchFilter(patch: Partial<FilterState>): void {
    this.filterSubject.next({ ...this.filterSubject.value, ...patch });
  }
}
HTML · template dùng async pipe 
<input type="text" placeholder="Tìm khoá học..." (input)="onSearchInput($any($event.target).value)">
<select (change)="onCategory($any($event.target).value)">...</select>

<ng-container *ngIf="result$ | async as r">
  <app-generic-list [items]="r.data" [itemTemplate]="courseTpl" emptyText="Không tìm thấy khoá học nào."></app-generic-list>
  <div class="pager">
    <button (click)="onPage(r.meta.page - 1)" [disabled]="r.meta.page <= 1">← Trước</button>
    <span>Trang {{ r.meta.page }} / {{ r.meta.totalPages }}</span>
    <button (click)="onPage(r.meta.page + 1)" [disabled]="r.meta.page >= r.meta.totalPages">Sau →</button>
  </div>
</ng-container>
