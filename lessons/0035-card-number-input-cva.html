<app-card-number-input> — CVA lần hai, tự format

Người dùng NHÌN THẤY "4111 1111 1111 1111". Backend nhận "4111111111111111". Một ControlValueAccessor đúng nghĩa là cầu nối giữa hai giá trị KHÁC NHAU đó.

⏱ ~40 phút · 🎯 Kết bài Module 7 — CVA lần ba (Bài 17, 18, giờ là đây)

🎯 Sau bài này bạn phải làm được
  • Phân biệt rõ "giá trị hiển thị trên DOM" và "giá trị thật trong FormControl" — và biết CHÍNH XÁC method nào của CVA xử lý chiều nào.
  • Viết logic format/parse hai chiều: số thô → chuỗi có dấu cách (hiển thị) và ngược lại (khi nhận giá trị từ model).
  • Kết hợp NG_VALUE_ACCESSOR (Bài 16) VÀ NG_VALIDATORS (Bài 18) trên cùng một component.
🌉 Bắc cầu từ cái bạn đã biết

Bài 16: writeValue nhận giá trị TỪ model, đẩy VÀO DOM. Bài 17: CVA đầu tiên (RatingInputComponent) — giá trị hiển thị và giá trị model là MỘT, giống hệt nhau. Bài 18: NG_VALIDATORS tự viết validator gắn liền với custom control. Bài này là lần đầu tiên hai giá trị đó KHÁC NHAU — buộc bạn hiểu CVA sâu hơn "4 method điền vào cho đủ".

1. Bài toán thật: hiển thị dễ đọc, model sạch cho backend

Số thẻ 16 chữ số liền nhau rất khó đọc và dễ gõ nhầm. Chuẩn ngành là hiển thị theo nhóm 4 số: 4111 1111 1111 1111. Nhưng backend xử lý thanh toán không cần (và không muốn) nhận dấu cách — nó cần đúng 16 chữ số liền.

Nếu bạn build control này XONG XUÔI như một <input> thường với [(ngModel)], giá trị model SẼ chứa dấu cách (vì đó là những gì DOM có). Bạn phải tự strip dấu cách ở NƠI KHÁC trước khi gửi API — logic bị rải rác, dễ quên một chỗ.

🤔 Trước khi nhìn lời giải

ControlValueAccessor có đúng 2 "cửa" dữ liệu đi qua: writeValue (model → DOM) và hàm bạn gọi trong (input) handler, thứ gọi onChange (DOM → model). Không có quy tắc nào bắt buộc dữ liệu đi qua 2 cửa đó phải NGUYÊN VĂN giống nhau — vậy bạn có thể "phiên dịch" ở đâu?

2. Mental model: 2 cửa, 2 chiều phiên dịch riêng

Sơ đồ luồng dữ liệu 
Model (FormControl.value)          DOM (input.value)
   "4111111111111111"      ──────▶  "4111 1111 1111 1111"
        (16 số thô)         writeValue    (có dấu cách, DỄ ĐỌC)

   "4111111111111111"      ◀──────  "4111111111111119999"
        (16 số thô,                  (người gõ, có thể thừa/thiếu)
         đã cắt/strip)      onChange

Hai hàm tiện ích thuần (không phụ thuộc Angular) làm toàn bộ việc "phiên dịch":

TypeScript 
function stripNonDigits(value: string): string {
  return value.replace(/\D/g, '');
}

function formatWithSpaces(digits: string): string {
  return digits.match(/.{1,4}/g)?.join(' ') ?? '';
}

3. Code đầy đủ

TypeScript · src/app/shared/components/card-number-input/card-number-input.component.ts 
@Component({
  selector: 'app-card-number-input',
  standalone: false,
  template: `
    <input type="text" inputmode="numeric" placeholder="1234 5678 9012 3456"
           [value]="displayValue" [disabled]="isDisabled"
           (input)="onInput($any($event.target).value)" (blur)="onTouched()" />
  `,
  providers: [
    { provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => CardNumberInputComponent), multi: true },
    { provide: NG_VALIDATORS, useExisting: forwardRef(() => CardNumberInputComponent), multi: true },
  ],
})
export class CardNumberInputComponent implements ControlValueAccessor, Validator {
  private readonly cdr = inject(ChangeDetectorRef);

  displayValue = '';    // "1234 5678 9012 3456" — CHỈ để hiển thị
  isDisabled = false;
  private rawDigits = ''; // "1234567890123456" — giá trị THẬT đưa vào model

  private onChange: (value: string) => void = () => {};
  onTouched: () => void = () => {};

  // ── ControlValueAccessor: model → DOM ──
  writeValue(value: string | null): void {
    this.rawDigits = stripNonDigits(value ?? '');
    this.displayValue = formatWithSpaces(this.rawDigits);
    this.cdr.markForCheck(); // zoneless (Bài 16) — writeValue không chạy trong event template
  }

  registerOnChange(fn: (value: string) => void): void { this.onChange = fn; }
  registerOnTouched(fn: () => void): void { this.onTouched = fn; }
  setDisabledState(isDisabled: boolean): void { this.isDisabled = isDisabled; this.cdr.markForCheck(); }

  // ── Sự kiện DOM thật: DOM → model ──
  onInput(rawInputValue: string): void {
    this.rawDigits = stripNonDigits(rawInputValue).slice(0, 16); // tối đa 16 số
    this.displayValue = formatWithSpaces(this.rawDigits);
    this.onChange(this.rawDigits); // model nhận DIGITS THÔ, không nhận chuỗi có dấu cách
  }

  // ── Validator (NG_VALIDATORS — Bài 18) ──
  validate(): ValidationErrors | null {
    if (this.rawDigits.length === 0) return null; // để required lo việc "bắt buộc nhập"
    return this.rawDigits.length === 16 ? null : { cardNumberLength: true };
  }
}
🔥 Vì sao writeValue KHÔNG gọi onChange

writeValue là model NÓI cho DOM biết giá trị — nó không phải người dùng gõ, nên KHÔNG được kích hoạt lại onChange (nếu không sẽ tạo vòng lặp vô nghĩa: model đổi → writeValue → onChange → model đổi lại → writeValue...). Chỉ có onInput (sự kiện DOM THẬT do người dùng gây ra) mới gọi onChange.

🔥 writeValue cũng phải stripNonDigits, không chỉ onInput

Nếu code gọi form.patchValue('4111-1111-1111-1111') (dấu gạch ngang thay vì dấu cách, ví dụ paste từ nguồn khác), writeValue nhận nguyên chuỗi đó — không strip trước khi format sẽ ra kết quả sai lệch. Luôn coi giá trị ĐẦU VÀO (dù từ DOM hay từ model) là "chưa đáng tin", chuẩn hoá trước khi dùng.

TypeScript

Validators.required kiểm "có nhập gì chưa"; validator TỰ VIẾT (cardNumberLength) kiểm "nhập đủ 16 số chưa" — hai lớp validate độc lập, đúng tinh thần Bài 18 (mỗi validator chỉ lo MỘT quy tắc).
