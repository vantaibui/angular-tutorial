Video Player — ViewChild + Directive appAutoPause

Lần đầu tiên trong khoá bạn "cầm tay" trực tiếp một DOM element có API riêng của nó — không phải đọc/ghi giá trị qua Reactive Forms, mà gọi thẳng .play()/.pause().

⏱ ~40 phút · 🎯 Mở Module 8 — @ViewChild và Directive đầu tiên của khoá

🎯 Sau bài này bạn phải làm được
  • Dùng @ViewChild để lấy tham chiếu tới một element trong CHÍNH template của component, và biết chính xác NÓ có giá trị từ lúc nào.
  • Phân biệt "đọc trạng thái của element" (dùng binding sự kiện Angular) và "điều khiển element" (dùng ViewChild gọi method) — không trộn lẫn hai việc.
  • Viết một Attribute Directive đầu tiên, dùng @HostListener lắng nghe sự kiện DOM thật.
🌉 Bắc cầu từ cái bạn đã biết

Suốt khoá tới giờ, mọi tương tác với DOM đều qua binding khai báo: [value], (click), *ngIf. Video player là bài toán KHÁC: bạn cần ra lệnh cho một element ("phát đi", "dừng lại") — không có cú pháp binding nào làm được việc "gọi một method tại một thời điểm tuỳ ý". Đây là lý do @ViewChild tồn tại.

1. Bài toán thật: điều khiển, không phải đọc/ghi giá trị

Trang học bài cần một nút Play/Pause tuỳ chỉnh (không dùng UI mặc định của trình duyệt cho MỌI thao tác). Bấm nút phải gọi được video.play() hoặc video.pause() trên đúng phần tử <video> trong template của component — TypeScript cần một cách "chạm tay" vào DOM node đó.

🤔 Trước khi nhìn lời giải

Angular biên dịch template thành code, và mỗi element trong đó tồn tại đâu đó trong bộ nhớ khi component đã render. Có decorator nào cho phép class TypeScript của component "xin" một tham chiếu tới CHÍNH element mà nó vừa khai báo trong template của mình không?

2. Mental model: @ViewChild chỉ có giá trị SAU khi view render xong

TypeScript · src/app/features/learn/video-player/video-player.component.ts 
@Component({ selector: 'app-video-player', standalone: false, templateUrl: './video-player.component.html' })
export class VideoPlayerComponent {
  @Input({ required: true }) src!: string;

  // Chỉ CHẮC CHẮN có giá trị từ ngAfterViewInit trở đi — template phải render XONG
  // (Angular đã tạo xong DOM node) thì ViewChild mới có gì để trỏ vào.
  @ViewChild('videoEl') private videoRef!: ElementRef<HTMLVideoElement>;

  isPlaying = false;

  togglePlay(): void {
    const video = this.videoRef.nativeElement;
    if (video.paused) {
      video.play();
    } else {
      video.pause();
    }
  }
}
HTML · video-player.component.html 
<div class="video-player">
  <video
    #videoEl
    [src]="src"
    appAutoPause
    controls
    (play)="isPlaying = true"
    (pause)="isPlaying = false"
  ></video>
  <button type="button" (click)="togglePlay()">{{ isPlaying ? 'Tạm dừng' : 'Phát' }}</button>
</div>

#videoEl là một template reference variable — cái tên bạn đặt cho element ngay trong HTML. @ViewChild('videoEl') tìm đúng element mang tên đó và trả về một ElementRef bọc quanh DOM node thật.

🔥 Vì sao KHÔNG dùng (play)/(pause) để làm luôn cả việc điều khiển

Nhìn kỹ template: isPlaying được cập nhật bằng BINDING SỰ KIỆN khai báo ((play)="isPlaying = true") — không cần ViewChild cho việc này. ViewChild CHỈ cần thiết cho việc togglePlay() phải ra lệnh gọi .play()/.pause() — thứ không có cú pháp binding khai báo nào làm được. Quy tắc chung: đọc trạng thái → binding khai báo; điều khiển bằng lệnh → ViewChild. Trộn lẫn hai việc (ví dụ tự addEventListener trong ngAfterViewInit để "đọc" trạng thái) tạo thêm một luồng dữ liệu ngoài tầm kiểm soát của Angular một cách không cần thiết.

3. Directive đầu tiên: appAutoPause

TypeScript · src/app/shared/directives/auto-pause.directive.ts 
// Gắn lên <video>: khi NÓ phát, mọi <video appAutoPause> khác trên trang tự dừng.
@Directive({ selector: 'video[appAutoPause]', standalone: false })
export class AutoPauseDirective {
  private readonly el = inject(ElementRef<HTMLVideoElement>);
  private readonly coordinator = inject(VideoCoordinatorService);

  // Lắng nghe sự kiện DOM THẬT — không quan tâm AI khiến video phát/dừng (người dùng bấm nút
  // trình duyệt, code gọi .play(), hay chính coordinator gọi .pause() trên video KHÁC).
  @HostListener('play')
  onPlay(): void { this.coordinator.notifyPlaying(this.el.nativeElement); }

  @HostListener('pause')
  onPause(): void { this.coordinator.notifyPaused(this.el.nativeElement); }
}
TypeScript · src/app/features/learn/video-coordinator.service.ts 
@Injectable({ providedIn: 'root' })
export class VideoCoordinatorService {
  private currentlyPlaying: HTMLVideoElement | null = null;

  notifyPlaying(video: HTMLVideoElement): void {
    if (this.currentlyPlaying && this.currentlyPlaying !== video) {
      this.currentlyPlaying.pause(); // trình duyệt thật sẽ tự bắn sự kiện 'pause' cho video đó
    }
    this.currentlyPlaying = video;
  }

  notifyPaused(video: HTMLVideoElement): void {
    if (this.currentlyPlaying === video) { this.currentlyPlaying = null; }
  }
}

Chọn selector video[appAutoPause] (không chỉ [appAutoPause]) — Directive này CHỈ áp dụng được lên <video>, khớp đúng với việc ElementRef<HTMLVideoElement> giả định kiểu cụ thể. Gắn nhầm lên <div appAutoPause> sẽ không khớp selector — lỗi bị bắt sớm thay vì runtime.

🔎 Vì sao coordinator gọi .pause() trực tiếp mà không cần "báo" Directive kia

@HostListener('pause') lắng nghe sự kiện DOM, không lắng nghe "ai gọi .pause()". Khi coordinator gọi otherVideo.pause(), trình duyệt tự bắn sự kiện pause trên chính otherVideo đó — Directive gắn trên nó tự động nhận được, gọi notifyPaused(), dọn state. Một nguồn sự thật duy nhất (sự kiện DOM), không cần hai component "gọi thẳng" lẫn nhau.

4. Chứng minh bằng test — và một giới hạn thật của jsdom

🔥 Phát hiện khi tôi verify bài này — jsdom KHÔNG implement <video>

Gọi videoElement.play() trong test in ra "Not implemented: HTMLMediaElement's play() method" và không hề bắn sự kiện play — khác hẳn trình duyệt thật. Test không được viết theo kiểu "gọi .play() rồi kiểm sự kiện có bắn không" (sẽ luôn thất bại trong jsdom). Thay vào đó:

  • Muốn mô phỏng "trình duyệt vừa phát video" → tự dispatchEvent(new Event('play')) thẳng, không gọi .play().
  • Muốn kiểm "code CÓ gọi .play()/.pause() không" → dùng vi.spyOn(video, 'play'), kiểm số lần gọi — không quan tâm việc phát có "thật sự" xảy ra trong jsdom hay không.
TypeScript · trích từ spec đã verify 
it('TC4 — video B bắt đầu phát → coordinator gọi .pause() trên video A (đang phát)', () => {
  const pauseSpyA = vi.spyOn(videoA, 'pause');

  videoA.dispatchEvent(new Event('play')); // A đang phát
  videoB.dispatchEvent(new Event('play')); // B bắt đầu phát

  expect(pauseSpyA).toHaveBeenCalledTimes(1); // coordinator tự dừng A
});
