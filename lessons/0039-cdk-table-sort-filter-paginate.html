CDK Table — sort / filter / paginate

Danh sách admin cần CỘT, không chỉ thẻ. CDK Table cho cấu trúc bảng "trần" — không theming, không CSS mặc định — bạn tự quyết định giao diện, CDK chỉ lo cấu trúc dữ liệu-cột-hàng.

⏱ ~45 phút · 🎯 CDK thứ hai của khoá (sau Drag & Drop, Bài 21)

🎯 Sau bài này bạn phải làm được
  • Dựng một bảng bằng CdkTableModule: cdkColumnDef, cdkHeaderCellDef, cdkCellDef, cdkRowDef.
  • Tái dùng NGUYÊN XI pattern debounce search + phân trang từ Bài 29 — không viết lại từ đầu.
  • Thêm sắp xếp CLIENT-SIDE trên dữ liệu trang hiện tại, phân biệt rõ với phân trang SERVER-SIDE.
🌉 Bắc cầu từ cái bạn đã biết

Bài 21: CDK Drag & Drop — "hành vi không giao diện", bạn tự viết CSS. CDK Table đi theo đúng triết lý đó cho bảng dữ liệu. Bài 29: debounce đúng chỗ (nguồn thô, không phải state đã gộp), distinctUntilChanged tránh gọi API thừa khi bấm lại trang cũ — tái dùng lại NGUYÊN VẸN ở đây, chỉ đổi nơi hiển thị kết quả từ thẻ sang bảng.

1. Bài toán thật: bảng, không phải lưới thẻ

Admin quản lý hàng chục, hàng trăm khoá học — xem dạng thẻ (Bài 38) không hiệu quả để so sánh nhanh giá, trình độ giữa nhiều dòng. Cần bảng: mỗi cột một loại dữ liệu, click tiêu đề cột để sắp xếp.

🤔 Trước khi nhìn lời giải

GenericListComponent (Bài 30) lặp qua mảng và uỷ quyền vẽ MỘT item cho template — nó không có khái niệm "cột". Bảng cần một cấu trúc khác: định nghĩa CỘT trước (tên, cách hiển thị), rồi lắp NHIỀU cột đó vào một hàng. Angular CDK có bộ nào tách đúng hai khái niệm này — cột định nghĩa RIÊNG, hàng chỉ LẮP RÁP các cột đã định nghĩa?

2. Mental model: định nghĩa CỘT trước, LẮP vào hàng sau

HTML · cấu trúc CdkTable 
<table cdk-table [dataSource]="courses">
  <!-- Định nghĩa MỘT cột: tên cột + cách vẽ header + cách vẽ ô -->
  <ng-container cdkColumnDef="title">
    <th cdk-header-cell *cdkHeaderCellDef>Tiêu đề</th>
    <td cdk-cell *cdkCellDef="let course">{{ course.title }}</td>
  </ng-container>

  <!-- Lắp các cột đã định nghĩa (ở TRÊN, có thể theo bất kỳ thứ tự nào) vào MỘT hàng -->
  <tr cdk-header-row *cdkHeaderRowDef="displayedColumns"></tr>
  <tr cdk-row *cdkRowDef="let row; columns: displayedColumns"></tr>
</table>

Tách biệt này cho phép đổi thứ tự cột chỉ bằng cách đổi mảng displayedColumns — không cần sắp xếp lại các khối cdkColumnDef trong template. Đây chính là ý tưởng "khai báo cấu trúc, lắp ráp riêng" — cùng tinh thần tách biệt với ngTemplateOutlet ở Bài 30, chỉ khác quy mô.

3. Code đầy đủ — tái dùng Bài 29, thêm sort

TypeScript · admin-course-table.component.ts 
const PAGE_SIZE = 10;

export class AdminCourseTableComponent implements OnInit, OnDestroy {
  readonly displayedColumns: string[] = ['title', 'price', 'level', 'actions'];
  courses: Course[] = [];
  page = 1;
  totalPages = 1;

  private sortKey: 'title' | 'price' = 'title';
  private sortDirection: 'asc' | 'desc' = 'asc';
  private lastSearch = '';
  private readonly searchInput$ = new Subject<string>();

  ngOnInit(): void {
    // Y HỆT Bài 29: debounce trên nguồn thô (bàn phím), KHÔNG trên state đã gộp.
    this.searchInput$.pipe(debounceTime(300), distinctUntilChanged(), takeUntil(this.destroy$))
      .subscribe((search) => this.load(search, 1));
    this.load('', 1); // KHÔNG debounce lần đầu — đúng lý do đã học ở Bài 29
  }

  // Sort CHỈ trên TRANG hiện tại — API (Bài 28-29) chưa hỗ trợ tham số sort.
  // Phân trang vẫn do SERVER quyết định (search/page tái dùng nguyên xi Bài 29).
  onSort(key: 'title' | 'price'): void {
    if (this.sortKey === key) { this.sortDirection = this.sortDirection === 'asc' ? 'desc' : 'asc'; }
    else { this.sortKey = key; this.sortDirection = 'asc'; }
    this.applySortInPlace();
  }

  private load(search: string, page: number): void {
    this.lastSearch = search;
    this.courseService
      .getAll({ ...(search ? { search } : {}), page, limit: PAGE_SIZE })
      .subscribe((res) => {
        this.courses = res.data;
        this.page = res.meta.page;
        this.totalPages = res.meta.totalPages;
        this.applySortInPlace();
        this.cdr.markForCheck(); // zoneless — .subscribe() thủ công gán mảng mới cho CdkTable
      });
  }
}
HTML · cột sort được bằng click header 
<th cdk-header-cell *cdkHeaderCellDef (click)="onSort('price')">Giá {{ sortIndicator('price') }}</th>
🔥 Vì sao sort KHÔNG đụng vào load() hay gọi lại API

API (Bài 28-29) chưa có tham số sort. Thêm nó cần đổi cả MSW handler lẫn service — ngoài phạm vi bài này. Giải pháp thực dụng: sort CHỈ áp dụng trên MẢNG ĐÃ CÓ (trang hiện tại), qua [...this.courses].sort(...). Hệ quả CẦN NÓI RÕ với người dùng: sort chỉ đúng TRONG một trang, không sort được toàn bộ tập dữ liệu qua nhiều trang — một đánh đổi thật, không phải thiếu sót.

6. Câu hỏi tư duy

Bảng hiện chỉ có 10 dòng mỗi trang. Nếu admin có 500 khoá học và muốn xem TẤT CẢ trong một trang cuộn dài (không phân trang bằng nút bấm) — render cả 500 dòng cùng lúc, dù chỉ khoảng 10 dòng hiện trong khung nhìn, sẽ khiến trình duyệt tạo ra 500 <tr> DOM node ngay lập tức.

Có cách nào để trình duyệt CHỈ thực sự tạo DOM node cho những dòng đang HIỂN THỊ trong khung nhìn, và tự tạo/huỷ khi người dùng cuộn — mà không cần bạn tự viết logic tính toán đó?
