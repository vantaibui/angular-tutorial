1. Interceptor — pipeline, không phải điểm chặn

TypeScript · khuôn chuẩn 
@Injectable()   // KHÔNG providedIn:'root' — phải khai tường minh qua HTTP_INTERCEPTORS
export class AuthInterceptor implements HttpInterceptor {
  intercept(req, next) {
    const authReq = token ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }) : req;
    return next.handle(authReq);
  }
}
// Đăng ký:
{ provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }  // multi:true — thiếu là GHI ĐÈ, im lặng
provideHttpClient(withInterceptorsFromDi())  // bắt buộc để class interceptor chạy ở v22
Sự thậtVì sao quan trọng
HttpRequest bất biếnKhông có .headers.set() — phải .clone() ra bản mới
Nhiều interceptor chạy theo thứ tự khai báoRequest đi xuôi, response đi ngược đúng thứ tự đó
Quên multi: trueInterceptor sau ghi đè interceptor trước — không lỗi, không cảnh báo

2. Refresh token — N request 401, 1 lần refresh

TypeScript · cờ chặn + cổng chờ 
private isRefreshing = false;                                    // chặn gọi refresh() lần 2
private refreshTokenSubject = new BehaviorSubject<string|null>(null);  // cổng chờ

// NGƯỜI ĐẦU TIÊN 401:
if (!isRefreshing) {
  isRefreshing = true; refreshTokenSubject.next(null);   // báo "đang refresh"
  return auth.refreshAccessToken().pipe(
    switchMap((newToken) => {
      isRefreshing = false;
      refreshTokenSubject.next(newToken);         // đánh thức MỌI người chờ
      return next.handle(addToken(req, newToken));
    }),
    catchError((err) => { isRefreshing=false; auth.logout(); router.navigate(['/login']); return throwError(() => err); }),
  );
}
// NGƯỜI TỚI SAU (isRefreshing đã true):
return refreshTokenSubject.pipe(
  filter((t): t is string => t !== null),
  take(1),                                       // tự huỷ sau 1 lần — không leak (Bài 02)
  switchMap((t) => next.handle(addToken(req, t))),
);
🔥 Bốn điều dễ sai
  1. Loại trừ /api/auth/* khỏi logic bắt 401 → thiếu thì refresh thất bại tự gọi lại refresh, vòng lặp vô hạn.
  2. catchError lồng TRONG nhánh refresh (bắt lỗi refresh thất bại), khác với catchError ngoài cùng (bắt 401 ban đầu) — hai tầng lỗi khác nhau.
  3. Thiếu take(1) ở nhánh chờ → subscription không tự đóng, lần refresh SAU vô tình kích hoạt lại request đã xong từ lâu.
  4. Test có router.navigate(['/login']) → route 'login' phải tồn tại thật trong provideRouter của test, nếu không NG04002 gây unhandled rejection âm thầm.
TypeScript · test bằng chứng: expectOne ném lỗi nếu refresh gọi >1 lần 
const p = firstValueFrom(forkJoin([http.get('/api/a'), ..., http.get('/api/e')]));
// cả 5 request gốc 401 ...
const refreshReq = httpMock.expectOne('/api/auth/refresh');  // ĐÚNG 1 — nếu >1 thì expectOne tự đỏ
refreshReq.flush({ accessToken: 'token-moi' });
// cả 5 request được retry ...
httpMock.verify();  // không còn request thừa

3. Auth state — một BehaviorSubject, hai cách đọc

TypeScript 
private readonly currentUserSubject = new BehaviorSubject<User|null>(null);
readonly currentUser$ = this.currentUserSubject.asObservable();       // subscribe liên tục (template)
readonly isAuthenticated$ = this.currentUser$.pipe(map((u) => u !== null));  // DẪN XUẤT, không Subject riêng
get currentUser() { return this.currentUserSubject.value; }         // đọc snapshot (Guard, Interceptor)
Nơi dùngCách đọcVì sao
Guard, Interceptor.currentUser / .accessToken (getter)Cần trả lời đồng bộ, không subscribe được giữa canActivate()
Template (Header)currentUser$ | asyncTự unsubscribe theo vòng đời component (Bài 03)
🔥 Đừng tạo BehaviorSubject<boolean> riêng cho isAuthenticated

Phải nhớ gọi .next() ở MỌI chỗ currentUser đổi — quên một chỗ là hai luồng lệch nhau. Dẫn xuất bằng map thì không thể lệch, vì nó được TÍNH chứ không được GÁN.

4. Path param vs Query param

Path — /courses/:idQuery — ?token=...
Trả lời"Tài nguyên nào?""Ngữ cảnh gì đi kèm?"
Route phụ thuộc nó?Có — thiếu thì 404Không — route vẫn khớp
Đọc bằngroute.snapshot.paramMap.get('id')route.snapshot.queryParamMap.get('token')
Ví dụ khác/courses/:slug?returnUrl=... (Bài 13), ?page=2&search=... (Bài 04)
🔥 Gõ nhầm paramMap ↔ queryParamMap

Cả hai đều có .get(), TypeScript không báo lỗi khi nhầm — chỉ nhận null bí ẩn dù URL có đúng tham số.

5. Bảo mật cơ bản

  • Không tiết lộ email tồn tại hay không — API forgot-password luôn trả cùng một thông báo (chống user enumeration).
  • 401 vs 403 (nhắc lại Bài 14): chưa đăng nhập → 401 → /login; sai quyền → 403 → /forbidden. Refresh token chỉ liên quan tới 401.
  • Guard là UX, không phải bảo mật (Bài 14) — interceptor cũng vậy; server luôn phải verify token thật.

7. Góc phỏng vấn

Câu hỏiTrả lời gọn
Interceptor hoạt động thế nào?Pipeline mà mọi request/response đi qua theo thứ tự khai báo (multi-provider). HttpRequest bất biến nên sửa phải .clone().
Tránh gọi refresh nhiều lần khi N request cùng 401?Cờ isRefreshing chặn gọi lại; BehaviorSubject<string|null> làm cổng chờ, request sau filter bỏ null + take(1) rồi tự retry.
Thiết kế state service an toàn?private Subject + public asObservable(); luồng dẫn xuất bằng map, không Subject riêng; đọc đồng bộ qua getter cho Guard/Interceptor.
Path param vs query param, chọn thế nào?Định danh tài nguyên bắt buộc → path. Ngữ cảnh tuỳ chọn, không ảnh hưởng route có khớp hay không → query.
