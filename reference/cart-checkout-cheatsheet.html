Cart & Checkout — cheat-sheet

Optimistic update + rollback, DI theo cấp, class Resolver, CVA hiển thị khác model.

Đã kiểm chứng: Angular 22.1.4 · 19 test xanh + tsc sạch

1. Optimistic update — chụp lại, đổi ngay, lùi nếu cần

TypeScript 
const previous = this.itemsSubject.value;              // 1. CHỤP state cũ TRƯỚC khi đổi
this.itemsSubject.next([...previous, item]);       // 2. Đổi NGAY — không đợi server
return this.http.post(...).pipe(
  catchError((err) => {
    this.itemsSubject.next(previous);        // 3. LÙI về snapshot nếu server từ chối
    return throwError(() => err);
  }),
);
🔥 Chụp previous TRƯỚC khi .next() optimistic, không phải sau

Chụp sau thì previous đã lỡ chứa state MỚI — rollback vô tác dụng. Luôn: chụp → đổi → (lỗi thì) lùi.

2. DI theo cấp — chọn nơi đặt providers theo VÒNG ĐỜI mong muốn

Đặt ởSống bao lâuDùng khi

🔥 root cho tiện có thể rò rỉ trạng thái giữa 2 phiên KHÔNG LIÊN QUAN

Checkout xong, rời đi, bắt đầu phiên checkout MỚI — nếu CheckoutStateService là root, coupon của lần TRƯỚC vẫn còn đó. Module-provided dựng lại sạch mỗi lần lazy module được tải lại.

3. Resolver — chuẩn bị dữ liệu, khác Guard (chặn điều hướng)

TypeScript 
@Injectable({ providedIn: 'root' })
export class CouponResolver implements Resolve<Coupon[]> {
  private readonly http = inject(HttpClient);
  resolve(): Observable<Coupon[]> {
    return this.http.get<Coupon[]>('/api/coupons').pipe(catchError(() => of([]))); // lỗi -> [] , KHÔNG chặn route
  }
}
// Gắn vào route:
{ path: 'coupon', component: CouponStepComponent, resolve: { coupons: CouponResolver } }
// Đọc trong component:
const coupons = (this.route.snapshot.data['coupons'] as Coupon[]) ?? [];

5. CVA nâng cao — hiển thị khác model

ChiềuViệc
writeValue(value)Model → DOMNhận giá trị model, CHUẨN HOÁ (strip), rồi format để hiển thị
onInput(rawValue) → onChange()DOM → ModelNhận input người gõ, CHUẨN HOÁ, gọi onChange với giá trị SẠCH cho model
🔥 writeValue KHÔNG được gọi onChange

Model báo cho DOM (writeValue) khác với người dùng gõ (onInput → onChange). Gọi onChange trong writeValue tạo vòng lặp sai ngữ nghĩa.

🔥 writeValue cũng phải chuẩn hoá input, không chỉ onInput

patchValue() có thể đưa vào chuỗi "bẩn" (dấu gạch ngang, khoảng trắng thừa) — writeValue phải tự strip trước khi format, không được tin dữ liệu đầu vào từ BẤT KỲ hướng nào.

6. Góc phỏng vấn

Câu hỏiTrả lời gọn
Optimistic update là gì, đánh đổi gì?Cập nhật UI NGAY trước khi server xác nhận, đổi lấy UX nhanh hơn — phải lưu snapshot state cũ để rollback nếu server từ chối.
Chọn cấp nào để đặt provider cho state chia sẻ giữa nhiều bước 1 tính năng?Module (lazy-loaded chứa các route con đó) — sống qua các bước, dựng lại sạch mỗi phiên mới. Không phải component (mất khi đổi bước) hay root (rò rỉ giữa các phiên).
Resolver khác Guard ở đâu?Cùng chạy trước khi kích hoạt route, nhưng Guard quyết định CÓ CHO VÀO không (boolean/UrlTree), Resolver CHUẨN BỊ DỮ LIỆU (giá trị thật, gắn vào route.data).
CVA có bắt buộc giá trị hiển thị và giá trị model giống nhau?Không. writeValue (model→DOM) và onChange (DOM→model) là 2 cửa độc lập — có thể format khác nhau miễn phiên dịch đúng cả 2 chiều.
