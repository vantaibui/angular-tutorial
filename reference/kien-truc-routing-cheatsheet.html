CourseService có providedIn:'root' nhưng nằm trong lazy chunk (chỉ lazy module import nó) — vẫn là singleton toàn app. AuthGuard cũng 'root' nhưng nằm ở main (vì AppRoutingModule eager import nó).

Món quà miễn phí: providedIn:'root' cho singleton và vẫn lazy/tree-shake được.

⚠️ Lazy module KHÔNG reset khi quay lại route

Chunk tải một lần; injector con sống tới khi reload trang → state được giữ. Muốn reset mỗi lần vào → đặt providers ở component.

4. Guard

TypeScript · khuôn chuẩn 
@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {
  private readonly auth = inject(AuthService);
  private readonly router = inject(Router);

  canActivate(route: ActivatedRouteSnapshot, state: RouterStateSnapshot): boolean | UrlTree {
    if (this.auth.isLoggedIn) return true;
    return this.router.createUrlTree(['/login'], { queryParams: { returnUrl: state.url } });
  }
}
Trả vềNghĩaDùng khi
trueCho qua—
UrlTreeHuỷ + chuyển hướng, một chu kỳMặc định khi cần redirect
falseChỉ huỷ, đứng nguyêncanDeactivate ("chắc chưa?")
🔥 Ba điều phản trực giác (đã verify)

1. await router.navigate(...) trả true khi guard redirect bằng UrlTree — redirect tính là thành công. Đừng dùng giá trị này để biết có bị chặn hay không; kiểm router.url.

2. route.data là Record<string, any> — gõ nhầm role thay roles không có lỗi biên dịch, và route admin thành công khai.

3. Guard là UX, không phải bảo mật. Chạy trong browser, bypass được bằng DevTools. Server vẫn phải kiểm quyền mọi endpoint.

Tình huốngHTTPĐi đâu
Chưa đăng nhập401/login?returnUrl=...
Đã đăng nhập, sai quyền403/forbidden — đá về login gây vòng lặp đăng nhập

canActivate: [A, B] chạy tuần tự, dừng ở guard đầu tiên không trả true. Nhưng viết guard đúng kể cả khi đứng một mình — đừng để tính đúng đắn phụ thuộc thứ tự trong mảng.

6. Generic API service

TypeScript 
// abstract + KHÔNG @Injectable: đây là KHUÔN, không phải dịch vụ (endpoint là gì?).
export abstract class GenericApiService<T extends { id: string }> {
  protected constructor(protected readonly http: HttpClient,
                        protected readonly endpoint: string) {}

  getById(id: string): Observable<T> { return this.http.get<T>(`${this.endpoint}/${id}`); }
  create(data: Omit<T, 'id'>): Observable<T> { ... }   // server sinh id
  update(id: string, patch: Partial<T>): Observable<T> { ... }
}

@Injectable({ providedIn: 'root' })     // providedIn ở lớp CON
export class CourseService extends GenericApiService<Course> {
  constructor() { super(inject(HttpClient), '/api/courses'); }
}
⚠️ Ba bẫy

1. HttpParams bất biến — p.set(...) trả object mới. Quên gán lại thì param bị mất, không lỗi, server trả trang 1.

2. Observable lazy — quên .subscribe() thì HttpTestingController báo "found none" và Network tab trống.

3. inject() trong super() hợp lệ (còn trong injection context); trong ngOnInit thì NG0203.

8. Góc phỏng vấn

Câu hỏiTrả lời gọn
Vì sao CoreModule cần guard chống import 2 lần? Lazy module import lại sẽ tạo injector con → bản thứ hai của mọi singleton. Đăng nhập ở bản A, trang lazy đọc bản B thấy null. Với multi:true thì interceptor chạy hai lần.
Lazy module có injector riêng không? Có, con của injector gốc. Service trong providers của nó là singleton trong module. Còn providedIn:'root' luôn về gốc, bất kể code nằm chunk nào.
false vs UrlTree trong guard? false chỉ huỷ, đứng nguyên, không phản hồi. UrlTree huỷ + chuyển hướng trong một chu kỳ, không race condition, và guard trở thành hàm mô tả ý định nên dễ test.
Phân quyền theo vai trò thế nào? Một RoleGuard đọc route.data['roles'] — tách logic khỏi cấu hình nên không nổ guard theo tổ hợp. Phân biệt 401 (→login) và 403 (→forbidden). Và luôn nói thêm: guard là UX, phân quyền thật ở server.
Mock API: MSW hay fake service? MSW — chặn ở tầng mạng nên HttpClient, interceptor, retry đều chạy thật; có backend thật thì không sửa file nào. Fake service phải viết lại toàn bộ và mọi test đều test bản giả.
