1. @ViewChild — khi nào cần, khi nào không

Việc cần làmCông cụ
ĐỌC trạng thái của element (video đang phát/dừng, input có giá trị gì)Binding khai báo: (play), (input), [value]
RA LỆNH cho element (gọi .play(), .focus(), đo .scrollHeight)@ViewChild + ElementRef.nativeElement
TypeScript 
@ViewChild('videoEl') private videoRef!: ElementRef<HTMLVideoElement>;
// CHỈ chắc chắn có giá trị từ ngAfterViewInit trở đi (hoặc từ 1 event handler bất kỳ,
// vì event handler chỉ chạy được SAU khi view đã render xong).
// Gọi sớm hơn (constructor/ngOnInit) -> throw vì videoRef còn undefined.

2. Attribute Directive + @HostListener

TypeScript 
@Directive({ selector: 'video[appAutoPause]', standalone: false })  // selector RÀNG BUỘC tag cụ thể
export class AutoPauseDirective {
  private readonly el = inject(ElementRef<HTMLVideoElement>);

  @HostListener('play')   // lắng nghe sự kiện DOM THẬT — không quan tâm AI gây ra nó
  onPlay(): void { ... }
}
🔥 Sự kiện DOM là nguồn sự thật, không phải "ai gọi method nào"

Khi service A gọi videoB.pause(), trình duyệt tự bắn sự kiện pause trên videoB — Directive gắn trên B tự nhận được, không cần A "báo" trực tiếp cho B.

4. Subject làm event bus — khác BehaviorSubject cho state

TypeScript 
@Injectable({ providedIn: 'root' })
export class ProgressEventBusService {
  private readonly lessonCompletedSubject = new Subject<string>();  // KHÔNG BehaviorSubject — đây là SỰ KIỆN
  readonly lessonCompleted$ = this.lessonCompletedSubject.asObservable();
  completeLesson(id: string): void { this.lessonCompletedSubject.next(id); }
}
Subject (event)BehaviorSubject (state)
Trả lời"Việc gì VỪA xảy ra?""Giá trị HIỆN TẠI là gì?"
Subscriber tới muộnBỏ lỡ mọi thứ đã quaNhận ngay giá trị hiện tại
🔥 Giới hạn thật: subscriber tạo SAU khi event đã phát thì bỏ lỡ vĩnh viễn

Đây là bản chất của Subject, không phải bug. Fix tạm: ReplaySubject(N). Fix triệt để: state tập trung bằng signal() + computed() (Module 13) — không có khái niệm "bỏ lỡ" vì không cần phát lại gì, chỉ đọc giá trị hiện tại.

6. Góc phỏng vấn

Câu hỏiTrả lời gọn
Khi nào dùng ViewChild thay vì binding khai báo?Khi cần RA LỆNH gọi method trên element (play/pause/focus), không phải khi chỉ cần ĐỌC trạng thái của nó (dùng (event) binding cho việc đó).
Vì sao Directive nên lắng nghe sự kiện DOM thay vì tự set state khi gọi method?Sự kiện DOM phản ánh trạng thái THỰC bất kể nguyên nhân (code gọi, người dùng, bên thứ ba can thiệp) — tự set state khi gọi method có thể sai lệch nếu có nguyên nhân khác.
Subject vs BehaviorSubject làm giao tiếp giữa component?Subject cho SỰ KIỆN nhất thời (subscriber muộn bỏ lỡ); BehaviorSubject cho TRẠNG THÁI liên tục (subscriber muộn nhận giá trị hiện tại ngay).
