1. Chọn flattening operator

Cả bốn đều "nhận outer → đẻ inner". Khác nhau duy nhất ở cách xử lý khi inner cũ chưa xong.

OperatorInner cũ chưa xong thì…Dùng choVí dụ EduCommerce
switchMap Huỷ cái cũ, chạy cái mới ĐỌC — chỉ cần kết quả mới nhất Search, filter, đổi route param
exhaustMap Bỏ qua cái mới GHI — chống double-submit Nút Lưu, Đăng nhập, Thanh toán
concatMap Xếp hàng, chạy tuần tự GHI — cần đúng thứ tự Ghi log, đồng bộ progress từng bài
mergeMap Chạy song song hết Độc lập, không quan tâm thứ tự Upload nhiều file cùng lúc
🧭 Cây quyết định 10 giây

Thao tác đọc → switchMap.
Thao tác ghi → thứ tự có quan trọng không? Có → concatMap. Không, chỉ cần chống bấm nhiều lần → exhaustMap.
Thật sự độc lập và song song được → mergeMap.

Nghi ngờ thì chọn switchMap cho đọc và exhaustMap cho ghi. Đó là hai lựa chọn đúng trong đại đa số trường hợp.

2. Pipeline search-as-you-type

TypeScript · khuôn chuẩn 
tuKhoa$.pipe(
  debounceTime(300),          // chặn: gõ 8 ký tự = 8 request
  distinctUntilChanged(),      // chặn: từ khoá trùng lần trước
  switchMap((t) =>
    searchApi(t).pipe(
      catchError(() => of([])),  // ⚠️ BÊN TRONG — xem mục 5
    ),
  ),
  takeUntil(this.destroy$),    // ⚠️ LUÔN CUỐI CÙNG — xem mục 4
).subscribe(...);

Thứ tự bắt buộc: debounceTime phải trước switchMap. Đảo lại là debounce nhầm kết quả thay vì debounce phím gõ.

⚠️ Đừng dùng BehaviorSubject cho sự kiện

Component mới mở sẽ nhận lại sự kiện cũ và bật toast ma. Trạng thái thì replay được; sự kiện thì không.

TypeScript · khuôn state service 
private readonly subject = new BehaviorSubject<User | null>(null);   // private: chỉ service ghi
readonly currentUser$ = this.subject.asObservable();                   // public: chỉ đọc
readonly isAuth$ = this.currentUser$.pipe(map((u) => u !== null));      // dẫn xuất
get current() { return this.subject.value; }                          // đọc đồng bộ (dùng dè)

4. Chống memory leak

TypeScript · pattern destroy$ 
private readonly destroy$ = new Subject<void>();

ngOnInit() {
  nguon$.pipe(/* ...mọi operator khác... */, takeUntil(this.destroy$)).subscribe();
}

ngOnDestroy() {
  this.destroy$.next();      // ⚠️ BẮT BUỘC — thiếu dòng này là leak nguyên vẹn
  this.destroy$.complete();
}
LuậtVì sao
takeUntil phải là operator cuối cùng Unsubscribe lan ngược từ subscriber lên nguồn. Operator đứng sau nó (nhất là switchMap) giữ subscription riêng và vẫn leak.
next() trước complete() Notifier chỉ complete mà chưa từng next → takeUntil "pass all values" → leak im lặng.
LuồngLeak?Xử lý
http.get()Không (tự complete)Vẫn cắt nếu callback có side-effect
interval, fromEventCótakeUntil bắt buộc
Subject trong service singletonCótakeUntil bắt buộc
| async pipeKhôngƯu tiên dùng cái này

5. catchError đặt đúng chỗ

TypeScript 
// ❌ NGOÀI: bắt được lỗi nhưng stream CHẾT VĨNH VIỄN sau lần lỗi đầu.
switchMap((t) => searchApi(t)),
catchError(() => of([])),

// ✅ TRONG: lỗi bị nuốt ở phạm vi 1 request, outer sống tiếp.
switchMap((t) => searchApi(t).pipe(catchError(() => of([])))),

Lý do: error là trạng thái kết thúc của Observable. Lỗi leo lên outer là giết luôn subscription gốc, trước khi catchError kịp thay thế.

7. Cold vs Hot

Cold (Observable)Hot (Subject)
Bao giờ chạykhi subscribe (lazy)khi .next()
2 subscriberchạy 2 lần (unicast)chạy 1 lần (multicast)
Ví dụhttp.get(), of(), interval()Subject và họ hàng

Hệ quả hay gặp nhất: hai | async trên cùng một Observable HTTP = hai request. Chữa: *ngIf="obs$ | async as x" (tốt nhất), hoặc shareReplay({ bufferSize: 1, refCount: true }).

Promise eager (chạy ngay khi tạo) và luôn bất đồng bộ. Observable lazy và phát đồng bộ được — chính tính lazy này là điều kiện để nó huỷ được.

8. Test RxJS bằng Vitest

TypeScript · khuôn test 
import { describe, it, expect, vi, afterEach } from 'vitest';

afterEach(() => vi.useRealTimers());   // ⚠️ quên dòng này → rò đồng hồ giả sang test sau

it('...', () => {
  vi.useFakeTimers();               // KHÔNG cần async — tua thời gian là đồng bộ
  // ...dựng stream...
  vi.advanceTimersByTime(300);
  expect(log).toEqual([...]);         // toEqual bắt được cả THỨ TỰ; toContain thì không
});

9. Góc phỏng vấn — 5 câu hay gặp

Câu hỏiTrả lời gọn
switchMap vs mergeMap? switchMap huỷ inner cũ khi có giá trị mới (unsubscribe → HttpClient abort XHR); mergeMap để chạy song song hết. Search dùng switchMap để tránh race condition.
Vì sao takeUntil phải cuối? Unsubscribe lan ngược từ subscriber lên nguồn. Nó chỉ complete phần chuỗi tính tới vị trí nó; operator sau nó vẫn giữ subscription riêng.
Cold vs hot? Cold: mỗi subscriber kích hoạt một lần chạy riêng (http.get → 2 subscribe = 2 request). Hot: dùng chung một luồng (Subject). Chuyển bằng shareReplay.
catchError trong hay ngoài switchMap? Trong. Ngoài thì stream chết vĩnh viễn vì error là trạng thái kết thúc.
Observable vs Promise? Observable lazy, huỷ được, nhiều giá trị, đồng bộ được, có operator. Promise eager, không huỷ được, một giá trị, luôn bất đồng bộ.
